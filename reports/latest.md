# 군중 상태 판정 인자 분리 — 밀집 이득·희박 악화로 미수용

## 1. 작업 목표
64개체 CPU 최적화를 계속하되 기각된 전체 snapshot에서 상태 판정 재사용이라는 한 요소만 분리한다. 이미 시험된 아이디어의 제한적 인자 분리이며 새로운 캐시 방식 전체를 처음 검증하는 것으로 기록하지 않는다.

## 2. 실제 수행
기존 전체 snapshot의 밀집 +5.38%·희박 +9.13% 국소 악화 보고서와 현행 Crowd 소스를 읽었다. mission-only subclass에서 pair의 Movable/EntryPressurePriority 결합 판정만 bool 배열로 저장했다. DEAD/위치/속도는 원래 객체에서 읽고 쌍 순서·힘 계산 순서·최종 플레이어 판정을 유지했다. 기존 512 합성 상태 행렬과 밀집/희박 각3쌍 하네스를 재사용했다. 초기화/배열 준비를 포함한 전체 Update를 블록당1000회, 가운데 쌍 역순으로 비교했다. 원본 코드·PBO·물리 검사·등반 재시도는 변경하지 않았다.

## 3. 측정 결과
512 합성 프레임과 후속6검사에서 pair/contact 수·접촉 힘·속도·압력 제안·진입 우선순위 불일치0. 밀집 원본 대비 raw TickCount 변화 [-20.33319237230359, -20.572308384052874, -20.775096180283338], 중앙 -20.5723%. 희박 [9.539535961402134, 4.262765314834449, 5.596615128579296], 중앙 5.5966%. 양수는 악화다. 밀집은 Update당2016 pair 후보, 희박0이다. 한 프로세스 내 반복이며 독립 실행3회가 아니다. raw TickCount 단위는 검증된 ms로 환산하지 않는다. 실제 NPC0, 전체 CPU/Present p50/p95/p99·8/64 기능·시각 품질은 미측정이다.

## 4. 원인 분석
확인: 전체 필드 복사와 달리 상태 판정만 재사용한 밀집 합성 비교는 세 쌍 모두 빨랐다. 희박에서는 세 쌍 모두 느렸다. 두 배치 모두 일관된 개선 및 중앙10% 이상이라는 사전 기준은 실패했다. 일반 적용 후보로 채택하지 않는다.
추정: pair가 많은 경우 반복 Movable 객체/상태 조회 감소가 이득을 낼 수 있고, pair0이면 전처리가 순수 추가 비용일 수 있다. 각각의 VM self-time은 측정하지 않았다. 현행64 전체 CPU에서 해당 부분의 점유율은 미분리다. 밀집 국소20%를 전체64 CPU20% 절감으로 해석하지 않는다.
미확인: 실제 혼잡 입력에서 pair 수 분포, 플레이어 접촉·콜백 재진입에서의 상태 일관성, 밀집 선택 전환 오버헤드. 밀집 전용 활성화는 이번 구현에 없으며 결과를 본 뒤 gate를 변경하지 않는다.

## 5. 검증 수준
Enforce 컴파일/합성 동등성 진단 성공. 일반 적용 국소 비용 gate 실패·미수용. 기능 회귀·전체 CPU 반복 검증·시각 품질·최종 수용은 미실행이다. 20ms p95 목표는 미달성 상태를 유지한다.

## 6. 변경 사항
기존 work-reduction-review1 아래 격리 미션·준비/실행/분석 스크립트와 작은 TSV만 추가했다. 신규 PBO나 서명 대상은 없다. 기존 입력 PBO10개와 서버987 해시는 실행기가 대조했다. 원본 Crowd 소스 해시도 전후 일치 확인했다. 캐시 수명은 한 Update 내부로 제한하며 마지막 플레이어 처리에는 적용하지 않았다.

## 7. 원시 증거
실행 ID ANIM-crowd-eligibility-factor1. source-proof.json에 source/fixture/mission SHA와 사전 기준을 저장했다. launch/plan/terminal 및 두 TSV와 script 로그를 보존했다. 512 상태 행렬은 OpenTraversal=true, 실제 네이티브 엔티티/플레이어 없음이다. 서버 종료 확인, 실제 exit=-1, forced=false. 보고서 저장 전 실행 프로세스 부재와 증거 해시를 검증했다.

## 8. 잔여 문제
이번 일반 적용 후보는 배포하거나8→64로 확대하지 않는다. 다음 의사결정은 기존 실제64 로그에 같은 pair 밀집도가 얼마나 있는지, 그리고 Crowd.Update가 전체 CPU에서 차지하는 비용이 충분한지에 달려 있다. 해당 기존 계측으로 분리되지 않으면 작은 국소 이득을 이유로 장시간 회귀를 시작하지 않는다. 접촉·지지 질의를 임의 삭제하거나 안전 성공을 강제하지 않는다. 클라이언트 전용 파트 실행 실패와 애니메이션 시각 판정은 별도 기존 결과를 유지한다.
