# 정적 경계 재사용 시험 및 기존 후보 판정 정정

## 1. 작업 목표

정상 밀침·낙하·착지·FOLLOW·재등반을 보존하면서 중복 계산을 줄일 국소 후보를 검토한다. 먼저 과거 순위 조기종료 후보의 실제 완료 기록을 대조하고, 단일 StaticMap 갱신 안의 정적 물체 Bounds 재사용을 분리 시험했다.

## 2. 실제 수행

기존 순위 후보의 함수/8명/64명/세 쌍 전체 비용 기록을 재사용했다. 같은 시험을 반복하지 않았다. 원본 PBO와 원본 StaticMap 소스의 packed script 바이트 일치를 확인했다. 새 후보는 격리 default-OFF 애드온이며 Update 경계에서만 캐시를 허용하고 위치행렬·로컬 충돌상자·크기·shape·동적 상태를 매 호출 확인한다. Ray/Sphere·지지·충돌 검사는 생략하지 않는다.

실제 DayZ 서버에서 NPC 없이 정적 물체 35개를 조회한 독립 프로세스 두 번, 물체 2개 조건 한 번을 실행했다. 매 실행 16쌍, 두 번째 밀집 실행은 순서 반전. 각 쌍은 8 epoch × 8 actor 상당 반복이며 캐시 생성/키 검사/해제도 측정 범위에 포함된다. 위치·회전·크기·동적 상태 변경, null, epoch 교체의 Bounds 결과를 비교했다. 직접 Begin/Bounds/End 경로만 시험했으며 실제 Update/Apply 결과 동등성은 아직 미검증이다.

첫 애드온은 Shape 식별자 충돌로 World 컴파일 실패했다. 식별자 수정 후 두 미션 버전은 나머지 연산/표현식 오류로 컴파일 실패했다. 이들은 측정 실행으로 세지 않고 원시 로그를 보존했으며, 해당 소유 서버만 검증 후 강제 종료했다. 마지막 수정 미션에서 세 측정 실행을 완료했다. 원본 게임 빌드는 변경하지 않았다.

## 3. 측정 결과

|---|---:|---:|---:|---:|---:|
| ANIM-bounds-method1d | 35 | 93173.5 | 43461.5 | -53.44% | 0 |
| ANIM-bounds-method2 | 35 | 89657.5 | 43447.0 | -51.60% | 0 |
| ANIM-bounds-sparse1 | 2 | 5514.0 | 2871.5 | -49.35% | 0 |

단위는 미보정 TickCount 원시 단위다. 함수 범위 경과값이며 CPU self-time 또는 전체 프레임 비용이 아니다. 밀집 각 실행은 arm당 35,840회, 희소 실행은 arm당 2,048회 Bounds 호출이다. 신규 8/64개체 기능·Present p50/p95/p99·애니메이션 표시 결과는 미측정이다. 세 실행 모두 완료/종료요청 marker 뒤 프로세스 종료를 확인했으나 실제 exitCode=-1이므로 정상 프로세스 종료 수용은 하지 않는다.

기존 순위 후보: 함수 구간 약82~83% 감소와 별개로 세 쌍 Present p95 변화는 −10.86%, +3.64%, +53.31%였다. 전체 비용 개선이 재현되지 않아 미수용이다. 64명 후보 실행에는 ENTRY_ALIGNMENT_NO_PROGRESS 한 건도 남았다. 기존 결함 계열과 같다는 사실만으로 신규 회귀가 아니라고 단정하지 않는다. 앞선 사전 검토에서 이 후보를 새 시험 대상으로 제안했던 것은 완료 기록 누락이었으며 이번에 정정한다.

## 4. 원인 분석

확인: StaticMap은 같은 기록의 월드 Bounds를 여러 actor에 반복 계산한다. 이번 고정 조건에서 유효 입력을 확인한 경계 재사용은 결과 불일치 없이 함수 범위를 줄였다. 추정: 시체가 많은 장면의 이 반복 계산을 줄일 가능성이 있다. 미확인: 실제 Apply/경로 무효화 동등성, 실제 모든 생존 64개체 프레임 효과, 경계 변화/삭제/다양한 엔티티에서의 완전성. 최초 생존 장면은 정적 기록이 적어 이 후보가 주요 물리 질의 병목을 해결한다고 볼 수 없다.

반증/미수용: 중첩 순위 판정의 함수 절감만으로 전체 프레임 개선을 주장할 수 없었다. 새 후보 역시 함수 결과만으로 배포하거나 20ms 달성을 주장하지 않는다. 캐시·할당·키 검사의 비용을 없다고 가정하지 않는다.

## 5. 검증 수준

기존 연구 중복 확인: 진단 성공. 격리 Bounds 결과: 진단 성공, 35개 조건 두 독립 실행. 희소 조건: 단일 실행. 실제 Update/Apply·8→64 기능: 미실행. 시각 품질: 이번 미측정. 전체 성능·최종 수용: 미완료. 사용자의 기존 14클립/8개체 시각 평가 성공은 보존하되 이번 캐시의 시각 검증으로 전용하지 않는다.

## 6. 변경 사항

새 실험 addon NFBoundsEpoch.c, config.cpp, build-bounds.ps1, 독립 미션/실행 manifest 및 분석 스크립트만 추가했다. 격리 PBO SHA-256: `114417D39AA89921AC50B550F98A810768AEF3EC197AD759AED42E8887F85037`. 서명 및 검증 성공, 개인키 미포함. 기존 게임/PBO/모델/운영 서버는 변경하지 않았다. 기본 OFF. 새 API·보간·애니메이션 틱 변경은 없다.

## 7. 원시 증거

실행 ID와 조건은 위 표 및 공개 JSON에 있다. 선정 패킷에는 실제 후보 함수, 미션, 원시 TSV 전체 32행씩, 최종 실행 상태의 비민감 필드와 내용 해시를 포함한다. 전체 로컬 로그·게임 자산·프로세스 정보·개인 경로는 공개하지 않는다. 기존 순위 후보 report-integrity의 두 결과 파일 해시를 재검증했다. 새 분석 재실행은 독립 반복으로 세지 않는다.

## 8. 잔여 문제

다음 단일 산출물은 실제 StaticMap.Update/Apply 결과의 OFF/ON 동등성 비교다. 장애물 목록·시그니처·Refresh/경로 무효화가 같고 후보가 실제 Update 경계에서만 재사용하는지 확인한다. 이 단계 실패 시 8/64 시험으로 확대하지 않는다. 통과해도 실제 전체 비용 이득을 확인하기 전 채택하지 않는다. 64명 정체 복구 반복·시체 착지 대기는 별도 결함으로 보존하고 이번 최적화를 기능 개발로 전환하지 않는다. 수집기 exitCode 누락은 다음 프레임 비용 시험 전 별도 최소 수정/검증이 필요하다.
