# 서버 업데이트로 비교군 분리

## 1. 작업 목표
셀 풀 비용 반복 전 실행 파일 무결성을 확인하고, Steam 서버 업데이트로 바뀐 비교 조건을 분리한다.
## 2. 실제 수행
기존 추가2쌍의 첫 서버 실행 전 pinned hash 검사가 실패했다. 서버/클라이언트/캡처는 시작되지 않았다. Steam content_log와 appmanifest를 확인해 서버앱223350의04:20:39~04:20:51 업데이트,321개파일 갱신,BuildID26220720 완료를 확인했다. 반복 대기중인 관리자 helper는 캡처요청/CSV 없음과PID·생성시각 확인 뒤 해당 helper만 종료했다. 기존 실행파일/캐시를 복원하거나 보안설정을 바꾸지 않았다.
새 server hash를 별도engine-26220720 비교군으로 고정했다. 같은PBO/8개체미션을 새 경로에서 실행했고 자동 등반·하강·재등반과 기존 상태계약을 확인했다. 클라이언트는 일반Steam으로 실행하고 완료뒤AltF4로 닫았다.
## 3. 측정 결과
새 엔진 8개체 단일 기능시험: active61.9496게임초,1912개체관측행,계약230행/전이144. 최종지지8/8·모든이정표8/8,낙하9·착지/FOLLOW복귀9. 상태연결/복구세대/최종정렬오류0. 풀생성8/재사용20912. 새 엔진의64 비용 실행은0이며 p50/p95/p99 미측정이다.
업데이트 전64 단일쌍 Present p95 OFF20.94/ON18.54ms,CPU20.80/18.38ms는 원래 비교군에 보존한다. 새 비교군의 독립 반복으로 세지 않는다.
## 4. 원인 분석
확인: 서버 해시가 EE1ADD8B…에서987FBC47…로 변경됐고 파일수정시각과Steam 완료로그가 일치한다. 표시 ProductVersion은1.30.164289.70으로 같아도 바이너리/데이터가 같다는 뜻이 아니다. 클라이언트 해시는E3BA9660…로 별도고정했다. 해시검사가 다른 엔진 결과 혼합을 막았다. 새 엔진에서 선택된8개체 기능은 유지됐으나 성능 변화나 전체 호환성을 증명하지 않는다. 과거네이티브주소/CPU표본을새바이너리에자동전용하지않는다.
## 5. 검증 수준
업데이트원인 진단성공. 새엔진8개체 단일기능회귀통과. 새엔진64기능/성능/화면·최종수용미완료. 서버RequestExit0뒤exit−1은여전히정상종료미수용. 클라이언트닫기뒤모든프로세스소멸확인. 비용재현성의판정은보류다.
## 6. 변경 사항
운영/원본PBO/모델/키변경없음. 기존셀풀PBO의서명검증성공상태유지. 새엔진시험미션/manifest/핀/업데이트발췌만추가. 과거고정해시계획은무효이력으로보존했다. 비용6실행을새로준비만했다. 기존프로세스CPU수집기의프레임판독6열을현재5열에맞춘격리adapter를준비했고CPU/QPC/identity논리는유지했다. 새64실행에서는Present와근접15초서버CPU·게임초·벽시계초를분리기록할계획이다.500ms시작지연한계를넘으면CPU근거로수용하지않으며정확프레임별self-time이라고주장하지않는다. 수집adapter는아직실제시험미실행이다.
## 7. 원시 증거

## 8. 잔여 문제
다음단일묶음은새엔진OFF→ON,ON→OFF,OFF→ON 총3쌍비교다. 모두같은엔진/미션/PBO/카메라/전투조건에서실행하고전체짝의방향과중앙변화를보고한다. 기존정책상서버CPU작업량과Presentp95의세짝개선·중앙5%기준을성능진전판단에사용하되20ms목표와별개다. 새비교군아직미실행. 결과가좋을때만64고저차전체기능·화면을확대확인한다. 기존기능결함해결로범위를확대하지않는다.
