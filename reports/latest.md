# 레인 간격 후보: 8개체 비교, 전체 비용 절감 미입증

## 1. 작업 목표

계산 재사용 외에 접촉 자체의 발생량을 줄일 수 있는지, 낮은 등반 진입 레인 간격 0.8→0.95m 단일 변경으로 선별했다. 충돌 반경·지지 판정·밀침·낙하·재등반은 유지했다.

## 2. 실제 수행

기존 코어를 수정하지 않고 기본 OFF인 격리 애드온을 빌드·서명·검증했다. 두 조건에 같은 누적 계측을 사용했다. 실제 Enforce 컴파일 및 생성된 3레인의 지지 검사 통과 후 동일 자동 8개체 씬에서 OFF→ON 1회씩 실행했다. 셀 풀 후보는 포함하지 않았다. 완료 후 클라이언트를 정상 닫고 서버·클라이언트·BE 종료를 확인했다.

## 4. 원인 분석

관찰: 후보의 접촉 쌍과 초당 solve는 줄었지만 완료가 늦어져 전체 body solve는 증가했다. 따라서 뭉침 완화 가능성과 실제 전체 비용 절감을 동일시할 수 없다. 추정: 정적 레인 간격만으로 동적 이동 중 접촉을 충분히 줄이지 못했을 수 있다. 반증 범위: 이 한 쌍은 '넓히면 전체 검사도 자동 감소한다'는 수용 근거가 되지 못한다. 일반적인 밀집 완화 효과 전체를 반증하지는 않는다.

## 5. 검증 수준

진단 성공·8개체 단일 회귀 통과. 반복 검증 완료 및 최종 수용 아님. 64개체 미실행. 정상 낙하 유지. 실제 서버 exit code -1이므로 전체 정상 종료 통과로 보고하지 않는다. 새 CPU 측정 없이 이 후보를 64개체 반복 시험으로 확대하지 않는다.

## 8. 잔여 문제와 다음 실험

레인 후보는 기본 OFF·미수용으로 보존한다. 다음 단일 산출물은 기존 물리 호출 소유자 자료에서 실제 중복 또는 불필요한 solve 조건을 한 곳 선정한 변경 가능성 명세다. 기능 개발로 확대하지 않고, 기존 Scratch·SupportSweepFast 실패를 재사용하여 충돌/지지 삭제 없이 전체 실행량을 줄일 수 있는지 판정한다. 64개체 CPU 목표와 애니메이션 최종 품질 수용은 여전히 별도 미완료다.
