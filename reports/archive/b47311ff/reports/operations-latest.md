# 64개체 내부 계측 제거 후보: 미수용·native crash로 배치 중단

## 1. 작업 목표
원래 지지·충돌 검사를 보존하고 내부 시간 계측 연산만 제거한 후보의 64개체 전체 CPU 효과를3쌍 비교하려 했다. 기능·시각·성능 수용은 별도다.

## 2. 실제 수행
동일13개 PBO·full250-node receiver·5개 표시 파트·총384native hosts, 고정 카메라1280×800/VSync0, 컨테이너 LOW_HOLD 고정 목표·공격OFF 조건을 사용했다. 순서는 control→candidate→candidate→control→control→candidate로 고정했다. 기존15초 외부 PresentMon과16점 서버 프로세스 CPU 표본·native callback clock를 사용했다. 처음3조건을 완료하고4번째 대조군에서 측정 시작 전 native crash가 발생해 남은5/6조건은 실행하지 않았다. 캡처 중 화면 조작·스크린샷을 하지 않았다.
앞선 retry2는 관리자 수집기 준비 영수증을 확인하기 전에 게임을 시작해 실제 캡처가 없었다. 이것은 진행 오류로 보존했으며 새 retry3에서는 수집기의 실제 준비·프로세스를 먼저 확인했다. 실행 정책 인자 누락은 확인됐지만 당시 조기 종료 오류가 기록되지 않아 원인으로 확정하지 않는다.

## 3. 측정 결과
| 실행 | Present p50 / p95 / p99(ms) | 서버 CPU(ms/게임초) |
|---|---|---:|
| 1 대조군 | 11.047 / 18.313 / 20.257 | 912.238 |
| 2 계측 OFF 후보 | 9.408 / 15.365 / 19.077 | 959.076 |
| 3 계측 OFF 후보 | 11.021 / 18.575 / 20.245 | 890.462 |

완료1쌍의 후보 변화: 서버CPU +5.134% (+46.837ms/게임초), Present p95 -16.097% (-2.948ms). native/game 비율 차이 -0.251%. 컨테이너 위 비율 차이 +11.058%p. 이 CPU 값은 스레드 합산 프로세스 사용량이며 프레임 시간이나 함수self-time이 아니다.
3번 후보는 대응하는4번 대조군이 실패했으므로1번과 임의 재짝짓기하지 않는다. 유효 캡처3건 모두 전체 화면/장면 gate 및64개체 timing/query 형식 검증 통과. 후보128개체 최종 행의 timing0은 명시적 unavailable이며 CPU0을 뜻하지 않는다. 각 캡처 생존receiver64 유지. 추적·등반·하강·피격·사망 전체 회귀나 실제 동작 영상 품질은 이번 비용 시험 대상이 아니다.

## 4. 원인 분석
관찰: 첫 쌍에서 화면p95는 낮아졌지만 서버CPU는 증가했고 작업량·군집 배치도 달랐다. 따라서 계측 제거의 순수 효과를 확정할 수 없다. 소스상 같은 물리 검사여도 실제 궤적과 접촉 횟수가 같다는 뜻은 아니다.
새 덤프는0xC0000005, faultRVA0x21a107이며 기존10개 caller RVA와 일치했다. 동일call chain은 동일근본원인 증명이 아니다. runtime memory patch·live attach·전체RE는 하지 않았다. 초기 stack reader가 CrashReporter.log를 선택한 빈 결과를 보존하고 crash_*.log로 고친v2만 판정에 사용했다.

## 5. 검증 수준
3쌍 중1쌍 완료+unpaired후보1건; 나머지는 crash로 중단. 첫 쌍 서버CPU 감소gate 실패 및 반복 검증 미완료로 후보 미수용. 국소구간 Presentp95가20ms보다 낮더라도 전체64개체20ms 목표 달성은 아니다. 기능 회귀·시각 품질 최종 수용 모두 아님.

## 6. 변경 사항
게임 코드·모델·PBO·서명·공용 실행기 변경 없음. 기존 서명검증된 입력을 해시 고정한 격리 실행만 사용했다. 분석JSON3개·interim-comparison·crash-fingerprint-v2·종료영수증을 추가했다. 이전 실패·덤프·로그는 덮어쓰지 않았다.

## 7. 원시 증거
실행ID ANIM-ct64-retry3-1-control, -2-timer-off, -3-timer-off, -4-control. capture-0/1/2의Present CSV·closed.json·server-process-cpu JSON/CSV와analysis-1/2/3에 원시해시가 연결돼 있다.4번 새dump SHA256:273a8f827348d54240e0da2e0838f0f030a622bc7d722d0b924f5bb595484273. 공개본은 로컬경로·PID·원시dump·개인키를 노출하지 않는다. 모든 게임·서버·PresentMon 종료 후 유휴 수집기만 신원검증해 중지했다.4번대기helper3개는 각각deadline 오류로 종료했으며 새 시험으로 세지 않는다.

## 8. 잔여 문제
계측 제거를 주력 서버CPU 최적화로 승격하지 않는다. 기존 SupportFast의질의감소/전체CPU증가, 축소receiver의클라이언트개선/서버미입증 결과와 함께 재사용한다. 직접 물리 질의/호스트 비용 감소 후보를 우선하되 현재 자료로 안전한 신규 큰 절감이 입증된 것은 아니다. 크래시로 완전한 반복 비교가 막혔으므로 같은 배치 재실행을 무작정 반복하지 않는다. 다음에는 재현된 client native fault의 소유자를 좁힐 최소 관찰이 개발 의사결정을 바꿀지 먼저 판단하고, 기능복구 개발로 범위를 확대하지 않는다.8개체 control milestone 실패와 전체 시각/기능 회귀는 별도 미완료로 유지한다.
