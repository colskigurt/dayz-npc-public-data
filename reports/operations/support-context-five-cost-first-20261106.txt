# 64개체 SupportFast 비용 수집 — 첫 ON 측정·기준 CPU 누락

## 1. 작업 목표
어댑터 없는 현행 5파트와 상태제한 SupportFast ON의 전체 서버 CPU 차이를 비교한다. 기존 8개체 기능 통과와 성능을 분리한다.

## 2. 실제 수행
기존 LOW_HOLD·기상 제어·카메라·Present 수집기를 재사용해 3쌍 순서를 준비했다. 서버 전체 TotalProcessorTime을 1초 간격으로 읽고 QPC·기존 게임/파트 시계를 연결했다. 게임 코드나 PBO를 새로 수정하지 않았다. 공통 미션에 기반 클래스의 누적 Fast 카운터만 추가했다.
첫 기준 실행은 Present 저장 후 CPU 시작 시간 식별 검사에서 실패했다. JSON ISO 값이 PowerShell DateTime으로 변환된 뒤 문자열 인자로 전달되며 소수점이 유실됐다. 명시 ISO 및 ticks 비교로 수정하고 살아 있는 같은 서버의 2초 진단으로 읽기를 확인했다. 이 2초 값은 비교에서 제외한다.

## 4. 원인 분석
확인: 현재 ON의 전체 서버 CPU를 실제로 읽었고, 이 단일 실행은 약1배의 게임 시간으로 진행했다. 첫 기준 누락은 수집 경로의 시간 정밀도 손실로 프로세스 소유권 검사가 거부한 것이다. 게임 기능 결함이나 성능 개선의 증거가 아니다.
미확정: 유효한 기준 CPU가 없으므로 절감률 계산 불가. 두 Present 단일값의 차이는 보존하되 반복 후보 효과로 판정하지 않는다. 관측 범위의 합계와 개별 self-time을 혼동하지 않는다.

## 5. 검증 수준
수집 경로 진단 성공·ON 단일 비용 관측 완료. 독립 반복·쌍 비교·후보 성능 수용은 미완료. 전체 고저차 회귀와 시각 품질은 이번 비용 씬의 판정 대상이 아니다. 양쪽 서버는 요청0 뒤 실제 종료-1, 강제 종료 없음. 클라이언트 닫기 입력 후 부재 확인, 종료코드는 미확인.

## 6. 변경 사항
기존 sample_horde_process_cost의 전체 CPU 읽기를 격리 출력·시작 시간 검증·QPC 원시값으로 제한 확장했다. 현재 후보 PBO1419E96D…는 기존 서명·검증본 그대로다. 신규 PBO0개, 배포본 미변경. 공통 미션과 실행 계획은 해시 고정. 첫 계획의 CPU/Present 동일 구간처럼 읽힐 표현은 실행 전에 분리 구간으로 정정하고 변경 영수증을 남겼다.

## 7. 원시 증거
실행 ID 위2개. 서버/클라이언트 프로필, Present CSV/closed/consumed, server-process-cpu.csv, 기존 game/native clock TSV, support-cost.tsv, cost-analysis.json 및 실패 판정 JSON 보존. 공개 패킷은 경로와 프로세스 정보를 뺀 집계 파생본이며 원시 로그 전체가 아니다. 동일 자료 재분석은 새 실행으로 세지 않는다.

## 8. 잔여 문제
현재3쌍 비교 미완료. 남은 사전 순서를 유지하고 누락된 기준은 필요 시 새 ID로 보충하며 실패 기록을 덮어쓰지 않는다. 3쌍 모두 서버 CPU 개선 방향·중앙5% 이상, Present p95 악화5% 이내, 게임/native 진행률 쌍 차이5% 이내와 동일 씬 조건을 사전에 고정했다. 느린 시뮬레이션을 절감으로 인정하지 않는다. 충분한 비용 근거 전 새 기능 개발이나 전체 장시간 회귀로 범위를 늘리지 않는다. 전체20ms·전투·시각 최종수용 미완료.
