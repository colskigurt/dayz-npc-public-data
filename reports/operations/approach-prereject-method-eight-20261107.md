# 접근 목적지 조기탈락 — 실제 메서드·8개체 검증

## 1. 작업 목표

실제 DayZ 연산을 줄일 국소 후보를 엔진 메서드→8개체 순서로 검증한다. 목적지 중심 바닥 검사 뒤 이미 점유된 후보를 조기 탈락시켜 주변 발판/후속 검사 작업을 줄인다. 기존 이동·밀침·낙하·착지·FOLLOW·재등반 안전 판정은 유지한다.

## 2. 실제 수행

원본 dg_lab_inputs.pbo의105개 구성 파일과 체크섬을 확인하고, 접근 계획 스크립트1개만 바꾼 격리 PBO를 생성했다. 다른104개 파일·prefix·자산·모델·그래프는 바이트 동일하다. 기존 B8FB 경로 재검증 wrapper는 그대로 super.Plan으로 연결된다. 새PBO 서명 및 DSCheckSignatures 검증 통과, 개인키 미포함. 기본OFF이며 새 시험 profile의 flag로만ON.

초기 메서드 미션2회는 변수명/스코프 컴파일 오류로 실행 전 실패했다. 각 원시 로그와 정확한 소유 서버 강제종료 receipt를 보존했다. 하네스 자체 forcedStop=false와 외부 종료 receipt의 차이는 별도 runtime-validation.json에서 effectiveForcedStop=true로 분류했다. 원시 기록은 덮어쓰지 않았다.

수정 후 실제 Floor·Claimed72조건을 비교하고, 사용자 허가로 Days Gone·디버그 도우미 종료 후 동일 메서드 OFF/ON 비용 블록을 실행했다. 이어 기존8개체 자동 통합 씬을 OFF→ON 한 번씩 실행했다. 기존 서버/Steam 클라이언트 실행기·종료 도구를 재사용했고 바탕화면 실행기나 운영 포인터를 새로 만들지 않았다.
