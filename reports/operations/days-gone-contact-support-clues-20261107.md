# Days Gone 충돌·지지 구조와 DayZ 적용 단서

## 1. 작업 목표

현재 자료로 Days Gone 충돌·지지 처리를 어디까지 설명할 수 있는지 확인하고, DayZ CPU 비용 절감에 유용한 단서를 선별한다. 기존 접촉 분석을 재사용하고 게임 코드 변경·새 게임 실행·대규모 재계측은 하지 않는다.

## 2. 실제 수행

10월25일 접촉 버퍼/지지/인과 기록, 보존된 Ghidra 의사코드·Capstone 어셈블리, 11월7일 CPU 분류, DayZ DGBNativeGround.c·DGBNativeCrowd.c를 대조했다. 지지 참조 +0x124/+0x126·레코드 stride 0x150, 제거 경로의 몸체 참조 +0x180/+0x188·접촉 stride 0x190은 저장된 어셈블리에서도 확인했다. 새 분석 엔진 초기화나 런타임 후킹은 하지 않았다. 검사한 DayZ Source가 현재 모든 시험 PBO와 같다는 별도 검증은 이번에 하지 않았다.

## 3. 측정 결과

새 플레이 측정은 없다. 기존 지붕 표시 1회: 등록300/비사망296, Present p95 24.771ms, 표시 간격 p95 20.091ms. 별도 CPU 7.841초/2584가중표본 중 미분류 leaf1531(59.25%). 물리 inclusive95(3.68%)·접촉 소비자 inclusive5(0.19%)는 전체 해당 기능 비용이나 self-time이 아니다.

기존 35.14초 인과 기록: 응답 적용15438건 중 live-peer 원인3건, 나머지는 nonmember_body. 15323건에서 기록된 queue 적용 재구성 residual<1e-3. 동시 같은 edge-cache origin 입장896그룹, 최대5명. 이 수치는 후킹한 과거 장면의 이벤트 기록이며 성능 처리율이나 이번296개체의 발생률이 아니다.

## 4. 원인 분석

### 확인된 흐름과 미확인 경계

접촉 생성/물리 질의 전체 소유자·갱신 주기 **미확인** → manager +0xb30/+0xb38의400바이트 접촉 버퍼 **확인** → 0x1404e6fd0이 몸체 참조·법선을 해석 **확인** → 0x1404e6150이 저장 플래그와 다른 member 참조를 따라 지지 판정 **확인** → job 완료를 기다린 뒤0x140501240이 공중 이력을 갱신 **확인**. 응답 큐→속도 기여도는 과거 런타임에서 일부 인과 확인. 모든 경우의 최종 힘·마찰·변위·애니메이션 연계는 미복구.

지지 predicate는 단순 플래그 하나만 읽는 함수가 아니다. member +0x124/+0x126의 참조를 따라 다른 0x150바이트 member 기록으로 이동하는 루프와 종료 비교가 있다. 정확한 모든 지지 그래프 의미나 복잡도 상한을 확정하지 않는다. 이 함수 안에 기하 질의가 없다는 사실은 앞단의 충돌 생성 비용이 없다는 뜻이 아니다. 프레임 간 무조건 재사용도 입증하지 않는다.

### 추가로 유용한 단서

1. **작업 버퍼 용량 유지:** 0x1404e3d40은 접촉/개체 수로 필요량을 정하고 +0x7c8/+0x7e0/+0x7f8 용량이 부족할 때 확장한다. 충분하면 사용 길이만 초기화하는 분기다. 매 갱신 무조건 해제·재할당 구조가 아니라는 정적 단서. 실제 할당률/절감량은 미측정이다. DayZ Scratch·셀 풀링 연구와 중복이므로 새 주요 후보로 포장하지 않는다.
2. **접촉 수명 관리:** 0x1404f7690의 개체 제거 경로는 몸체를 참조하는 접촉 레코드를 지우고 멤버 배열을 압축한다. 오래된 참조가 남지 않게 하는 구조다. 사망 즉시 이 함수가 호출된다거나 시체가 모든 물리에서 제외된다는 뜻은 아니다. DayZ의 DEAD pair 제외는 이미 존재하고 시체의 월드 질의 참여는 별도 문제다.
3. **자료 배치·일괄 소비:** member/변환/상태·접촉 배열과 job 분할이 구분된다. 기존 member50단위·contact최소200단위는 병렬 작업 분할이며 프레임당50명만 갱신한다는 증거가 아니다. Enforce Script에 같은 네이티브 스레딩 경로가 있다고 가정하지 않는다.
4. **지형 정보와 개체별 실행 분리:** 같은 ledge cache origin을 여러 개체가 공유하면서 자기 위치로 투영한 결과를 쓰는 기존 증거가 있다. 이는 서로 다른 endpoint의 충돌 결과까지 공유한다는 뜻이 아니다. DayZ 기존 edge/fixture 캐시와 중복부터 확인해야 한다.

### DayZ에 주는 판단

검사한 소스에서 DriveGround는 이동 후 SolveContacts를 커밋하고, Displace는 별도 next와 minimumLift로 Floor·3높이 world sweep·SolveContacts를 실행한다. Contacts는 다음 swept trajectory의 시작점이므로 첫 검사를 삭제하거나 결과를 두 번째에 복사하면 의미가 달라진다. 기존42쌍 입력 완전일치0과 단일solve 보류 결론을 뒤집지 않는다. Days Gone 자료는 '반복 질의를 없애면 된다'는 증명이 아니라 **접촉 생성→지지/응답 소비의 소유·수명 분리**를 검토할 근거다.

## 5. 검증 수준

기존 정적 분석 재검토 + 일부 저장 어셈블리 교차 확인 + 과거 런타임 근거 연결. 새 기능 회귀/반복 성능 검증/최종 수용 없음. 접촉/지지 독립 비용 분류 성공으로 보고하지 않는다.

## 6. 변경 사항

분석 JSON·보고서만 추가. DayZ/DG 실행파일·게임 소스·PBO·서버·기존 원시 증거 변경 없음. 빌드 SHA-256 `17c2fca01d566914147a6d4924d038cb1f5a822c2829e4c45862e2bf837730b3`. 서명 작업 해당 없음. 기존 게임·디버그 환경은 조작하지 않았다.

`contact-support-implementation-readiness-2026-10-25.json`, `contact-source-causal-20261025/source-causal-analysis.json`, `focused/0x1404e3d40.c`, `focused/0x1404e6150.c`, `focused/0x1404f7690.c`, 두 저장 Capstone 파일, 검사한 DayZ 소스2개. 상대 ID·해시를 공개 JSON에 제공하며 로컬 절대경로·원시 메모리·프로세스 식별자는 공개하지 않는다. 원본은 보존했다.

## 8. 잔여 문제

가장 가치 있는 다음 산출물은 **현행 후보의 접촉 질의 소유·커밋/rollback·재사용 금지 조건 결정표**다. 기존11월4일 단일solve/11월7일 소유계약·Scratch·셀풀 연구를 우선 재사용해 이미 기각된 병합을 반복하지 않는다. 새 기능 개발로 확대하지 않는다. Days Gone의 전체 접촉 생성자가 확인되지 않아도 현행 DayZ 두 단계 의미가 다르다는 판단은 가능하다. 추가 DG 계측은 '특정 접촉 결과의 생성/소비 갱신 번호와 수명'처럼 결과가 구현 결정을 바꿀 단일 질문이 남을 때만 수행한다. 현재 자료로 개선율을 제시하거나 새 최적화 코드를 수용하지 않는다.
