# 호스트 물리 속성 진단 및 64개체 시험 조건 정정

## 1. 작업 목표

표시용 호스트의 물리 바디 속성을 읽고, 앞선 평지 64개체 시험의 실제 전투 설정과 호스트 수를 정정한다.

## 2. 실제 수행

기존 PBO를 변경하지 않고 전투 OFF/ON 진단 미션에서 각각 3회 읽었다. 물리 setter는 사용하지 않았다. 기존 실패한 NOCOLLISION 변경은 반복하지 않았다.

## 3. 측정 결과

전투 OFF: 8개체, 표시 호스트 40개, 120행. 전투 ON: 표시 40개와 피해 수신 8개, 144행. 모든 관측 바디는 layer 524288, solid/active/dynamic true였다. 같은 레이어·캐릭터·지형 상호작용 허용, 건물 상호작용은 false였다. 전투 ON의 모든 역할에서 mass getter 70, 모델 충돌 경계 (-0.28,0.05,-0.28)~(0.28,1.65,0.28)를 읽었다. 이를 논리 개체의 합산 질량이나 전체 충돌 형상으로 해석하지 않는다.

**기존 보고 정정:** approach-prereject-flat64-screen-20261107은 CombatEnabled=false이며 64개체·320개 표시 호스트, 피해 수신 호스트 0개 조건이다. 별도 피해 수신 객체를 포함했다는 이전 설명은 잘못됐다. 원시 지표는 변경하지 않는다. OFF/ON 서버 CPU는 788.233/828.377 ms/게임초(+5.09%), Present p95 13.133/13.935ms였다. 해당 후보는 선별 기준 미달이며, 전투 포함 성능이나 전역 20ms 목표 달성으로 인정하지 않는다.

## 4. 원인 분석

확인: 표시 전용 역할도 물리 바디를 보유한다. 미확인: 실제 접촉 수, 바디별 비용, 네이티브 형상 전체, 이 바디들이 현재 비용 증가를 얼마나 설명하는가. 상호작용 허용은 접촉 발생 증거가 아니다. 이전 레이어 변경 실패를 무시하고 물리를 끄는 결론을 내리지 않는다.

## 5. 검증 수준

읽기 전용 진단 성공. 기능 회귀·시각 품질·성능 개선은 이번 시험의 평가 대상이 아니다. 두 클라이언트 정상 종료를 확인했다. 서버는 종료 요청 후 exit -1로 끝났으므로 정상 프로세스 종료 통과로 보고하지 않는다.

## 6. 변경 사항

격리 진단 미션과 결과 요약만 생성했다. 원본 게임 코드, 배포 PBO 및 기존 보고서·원시 자료는 보존했다. 게임 빌드와 서명물을 변경하지 않아 새 서명 대상은 없다.

## 7. 원시 증거

실행 ID: ANIM-host-physics-readback1, ANIM-host-physics-readback2-combat. 증거: cohort-correction-audit.json, 각 host-physics-state.tsv 및 client-closed.json. 로컬 체크포인트에 SHA256과 전체 경로를 기록한다. 공개 JSON에는 민감 경로와 프로세스 ID를 제외한다.

## 8. 잔여 문제

다음 단일 산출물은 표시 호스트 물리 비용을 분리할 수 있는 최소 통제 비교 설계다. 실제 비용 근거와 수명·위치 계약 보호 조건을 제시하기 전 물리 레이어 변경, 바디 제거 또는 대규모 회귀를 시작하지 않는다. 이전 NOCOLLISION/부모 연결 실패와 기존 비용 자료를 먼저 대조한다.
