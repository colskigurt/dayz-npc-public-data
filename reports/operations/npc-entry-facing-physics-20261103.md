## 1. 작업 목표

입구 방향 유지 후보가 짧은 위치 보정에서 방향 전환을 피하면서 기존 물리 차단을 보존하는지 확인한다. 안전한 추가 진전이 없거나 범위가 누출되면 실제 8·64개체 시험으로 확대하지 않는다.

## 2. 실제 수행

검증된 기존 동결 하네스에 직접 MoveTo 물리 호출 22회와 실제 Walk의 허용 범위 검사 36회를 추가했다. 물리 호출에는 고정된 원본 수평 이동량 0.02m를 공급했다. Walk 범위 검사는 DriveGround를 잠금 관찰 전용 하위 클래스로 대체하므로 실제 전체 이동 실행과 구분한다. 프로필의 entry-facing.flag 읽기도 검사했다. 모듈 자체는 기본 OFF이며, 시험 프로필에서만 ON이다.

## 3. 측정 결과

유효 배치 1회다. 후진·옆 보정에서 OFF는 이동하지 않고 각각 -6도/+6도로 방향을 바꿨다. ON은 방향 0도를 유지하고 각각 0.0195313m/0.0200195m 이동했으며 종료 관절 검사를 통과했다. 세계 좌표 부동소수점 양자화 비교에만 0.001m 여유를 사용했고 물리 임계값은 변경하지 않았다.

일반 전진·이동량 0·남은 거리 제한·비네이티브 경로의 결과는 OFF/ON이 같았다. 개체·플레이어·벽 차단은 이동 0으로 유지했다. 실제 Floor 결과로 보정한 발판 끝은 FOOTPRINT_UNSUPPORTED, 발판 밖 목표는 VERTICAL_LINK_REQUIRED로 거절했다. 허용 범위/일시 잠금 복원 36회와 기존 안전 검사 66행을 대조했다. 기존 66행은 원본과 동일했다.

새 후보의 8·64개체 추적, 실제 애니메이션 부드러움, p50/p95/p99, Present/CPU busy/GPU, 할당·GC는 미측정이다. 이전 64개체 46/64 실패는 해결된 것으로 바꾸지 않는다. 20ms p95는 목표다.

## 4. 원인 분석

제한된 물리 조건에서는 이동량을 늘리거나 몸을 즉시 회전시키지 않고 짧은 보정이 가능했다. 실제 재등반 지연의 원인이 해결됐다는 증거는 아니다. 밀침이 보정 속도를 이기거나 애니메이션에 발 미끄러짐이 생길 수 있다.

첫 실행은 시험 미션의 배열 값 뺄셈 표기에서 파서 오류가 났다. 두 번째 실행은 범위 검사 출력이 깨졌고 절벽 시험점도 실제 발판 끝이 아니어서 전체 수용하지 않았다. 세 번째 실행은 출력 형식과 실제 지지 광선으로 시험점을 보정한 배치다. 세 번의 성공 반복으로 세지 않는다. 후보 PBO는 세 실행에서 같았다.

## 5. 검증 수준

후보의 World/Mission 엔진 컴파일과 제한 물리·범위 진단은 성공했다. 벽 사례는 시작부터 네이티브 자세가 일부 차단된 조건이어서, 새로운 벽 접촉의 전체 몸 사례까지 검증했다고 하지 않는다. Walk는 실제 허용 범위 함수를 실행했지만 이동 본문은 관찰용 대체였다. 실제 추적 회귀·반복 검증·시각 품질·성능·최종 수용은 미완료다.

## 6. 변경 사항

기존 51FA02BE 계열의 서명된 nf_entry_facing 후보를 그대로 사용했다. 새 PBO나 원본 자산 변경은 없다. 시험 미션만 격리했고 시험 뒤 기존 하네스의 위치·자세·접촉 상태를 복원했다. 검증된 서명·PBO 내용 대조는 이전 빌드 증거에 연결한다. 개인 키는 배포물에 없다. 시험 서버는 owned cleanup으로 닫혔으며 정상 quit 검증은 아니다.

## 7. 원시 증거
