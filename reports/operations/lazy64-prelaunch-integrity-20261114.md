# 64개체 비용 비교 사전 입력·기록 정합성 점검

## 1. 작업 목표
중단된64개체 lazy eligibility 비교를 이어가기 전 현행 입력과 기록 귀속을 확인한다. 원래CPU 채택 기준과 기능·시각·Present 독립 판정은 바꾸지 않는다.

## 2. 실제 수행
기존 PBO13개와 서버·클라이언트·미션·수집기4개, 총17개 입력을 계약 SHA와 대조했다. 모두 일치했다. 아직 runs가 없는 준비본임을 확인했다. 계약서의8개체/mode4 sweep 생략 문구는 이전 진단에서 남은 것으로, 현재64개체/원래 물리 검사 유지/eligibility만 변경한다는 문구로 정정했다. 분석기의 고정된 과거 run ID도 contract sourceRunId를 읽도록 정정했다. invalid condition receipt가 있으면 분석을 거부하고 기존 analysis.json을 덮어쓰지 않도록 했다. 변경 전후 SHA와 patch를 보존했다.

## 3. 측정 결과

## 4. 원인 분석
확인: 시험 본체와 입력은 바뀌지 않았지만 메타데이터에 이전8개체 관절 검사 생략 진단 문구와 과거 run ID가 남아 있었다. 수정하지 않으면 새 자료가 잘못 귀속될 위험이 있었다. 실제 guard는 이미64/64 host를 검사했으며 이번 정정으로 물리 생략 후보로 바뀐 것이 아니다.
미확인: 세 번째 유효 비용 비교, 실시간 정상 종료 guard,64기능·Present·시각 수용. foreground 전용 시간이 필요한 조건은 유지한다. 다른 세션은 별도 Unity 작업을 조율 중이므로 단순 프로세스 부재를 전체 사용 허가로 해석하지 않는다.

## 5. 검증 수준
사전 무결성 점검·기록 오류 정정 완료. 실제 게임 비교 미실행. 성능 채택·기능 회귀·시각 품질·최종 수용 아님.

## 6. 변경 사항
