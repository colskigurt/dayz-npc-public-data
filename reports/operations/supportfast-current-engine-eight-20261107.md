# SupportFast: 현행 엔진8개체 기능 통과, CPU 효과 미측정

## 1. 작업 목표
기존 상태 제한 SupportFast 후보를 현행 서버 빌드에서 검증한다. 결과 재사용 대신 실제 지지 검사량 감소 후보이며, 정상 밀침·낙하·착지·추적·재등반을 보존하는지 먼저 확인한다.

## 2. 실제 수행
기존 PBO 1419E96D11A984951CDD48B926D7E6604413F1B9D74729D8FE55118BAF86E2BC를 재사용했다. 게임 코드·PBO는 새로 변경하지 않았다. 8논리 개체, 40표시 파트와 원본 전체 골격 수신기8개(총48호스트), 공격 OFF 조건에서 LOW→HIGH→DOWN→재등반을 실행했다. 계측 카운터만 추가한 시나리오다. 준비 완료 후 시작 게이트를 열었으며 준비 대기 시간은 활동 시간에서 제외했다.

## 3. 측정 결과
후보:81.5118게임초, 유효 최종8/8, 전체 경유8/8, 낙하9회/착지 후 FOLLOW9회. 상태 체인·복구 세대·최종 정렬 오류0. SupportFast 17,528회, 생략 광선70,112회, 모든 개체에서 사용 및 skipped=4×used 일치. 원본 수신기 Jaw/spine2 바인딩8/8 유지.
기준 실행 ANIM-receiver-eight2-1-control:61.7949초,8/8,낙하8/복귀8. 단일 비동시 비교이며 후보 완료 시간은 약31.9% 길었다. 이동 이력·낙하 횟수가 달라 시간 차이를 순수 CPU 효과로 해석하지 않는다. p50/p95/p99·CPU·영상 부드러움은 이번 시험에서 측정하지 않았다.

## 4. 원인 분석
관찰 사실: 제한 조건에서 광선 검사가 실제 감소했고8개체 기능 계약이 통과했다. 추정: 제한된 평탄 발판 구간의 추가 광선을 줄이면 물리 질의 비용을 줄일 수 있다. 미확인:64개체 전체 CPU 이득, 접촉 분포 변화, 시각 품질, 반복 재현성. 호출 수 감소만으로 성능 개선을 입증하지 않는다. 기존 실패·구엔진 로그는 보존하고 새로운 독립 반복으로 합치지 않는다.

## 5. 검증 수준
단일 기능 회귀 통과. 성능 미실행, 시각 품질 미평가, 반복 검증·최종 수용 아님. 종료 요청0 뒤 실제 서버 종료 코드는-1이므로 정상 종료는 불수용이다. 서버 프로세스 종료 및 클라이언트 Alt+F4 종료 후 잔존 프로세스 없음은 확인했다.

## 6. 변경 사항
기존 SupportFast PBO와 현행 게임 코드를 유지했다. 새로운 파일은 격리 시험 시나리오의 카운터 관찰, 분석 JSON, 본 보고서뿐이다. 현행 서버 SHA987FBC47BAB1DAB37F74D7F700AA2E5B6AF936A7181A62F5BA9F0090AEBBA805. 이전 서버EE1ADD8B 비용 자료와 혼합하지 않는다. 기존 서명 사전 검증 성공; 새로운 PBO·서명 생성 없음.

## 7. 원시 증거
실행 ANIM-support262-eight1-on, 기준 ANIM-receiver-eight2-1-control. 로컬 체크포인트에서 분석·원시 상태·지지 카운터·시나리오·사전 검증·실행 종료 기록14개 파일의 해시를 검증하고 보존했다. 체크포인트 SHA-256은 공개 JSON에 연결했다. 원시 파일 자체는 이 공개 보고서에 포함하지 않았다. 외부 공개 자료에는 로컬 경로·프로세스 식별자를 제외한다.

## 8. 잔여 문제
64개체 CPU/Present 반복 비교가 필요하다. 기존 SupportFast 조건과 시계 비교 기준을 보존하고, 최근 성공한15초 동시 CPU/Present 수집기를 재사용한다. 원본 수신기 유지 및 단일 요인 비교로 수신기 경량화와 혼합하지 않는다. 64개체 고지대 기능·실제 피격·시각 품질·전체20ms 목표는 미완료다. 이번8개체 결과로 성능 성공을 선언하지 않는다.
