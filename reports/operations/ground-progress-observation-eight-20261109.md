# 경로 접선·접촉 변위 8개체 관측

## 1. 작업 목표
기존 로그에서 빠진 실제 경로 접선과 접촉 변위 시도/성공/거부를 짧게 관측해 접근 감속의 필요성을 판단한다. 지상 감속·등반 제한은 적용하지 않는다.

## 2. 실제 수행
기존 14개 입력 PBO와 별도 관측 모듈 1개를 사용했다. DGBGroundAgent.MoveTo와 DGBNativeCrowd.Displace를 감싸 원래 super 호출 결과를 그대로 반환했다. 경로가 남아 있을 때 직전 MoveTo 원점/다음 waypoint/route revision/관측시각을 기록했다. 신선도 0.1초, 같은 경로세대·waypoint 조건에서만 접선 투영을 계산했다. 접촉 변위에서 실제 진입/결과와 내부 ContactSolves 증가량을 집계했다. 이동 입력·충돌·지지·밀침·낙하·등반 재시도 정책을 수정하지 않았다.
초기 관측 모듈의 null body 보호를 보완한 runtime2를 사용했다. 기본 거부 경로에서 원래 false/위치/솔버 수를 보존하는 Enforce 검사 통과. 첫 eight1 씬은 기존 row 변수와 중복되어 컴파일 실패했고 소유 서버를 강제 종료했다. 원본 실패 기록을 보존하고 관측 변수만 이름을 바꾼 eight2로 진행했다. 이 실패 실행은 반복 측정으로 세지 않는다.

## 3. 측정 결과
8개체 단일 관측 60.0034초 완료. 접촉 변위 3305시도 = 3121성공 + 184거부. 그 내부 솔버 증가량 3280회, 전체 솔버 증가량 13149회. 약24.94%는 호출수 비율이며 CPU 비용 비율이 아니다.
유효한 신선 경로 표본에서 지상 이동 요청 유지 구간 누적61.579개체·초의 평균 실제 속도2.722m/s, 경로 접선 진행2.701m/s. 진행0.05m/s 미만 비율은 약0.84%였다. 따라서 이번 소규모 장면에서는 지속적인 지상 저진행을 재현하지 못했다.
정렬 구간 누적24.674개체·초는 실제0.385m/s, 접선0.162m/s, 접촉 변위12.56회/개체·초였다. 이동 요청 유지 구간은8.72회/개체·초였다. 둘의 상태·위치·밀도가 달라 인과 비교가 아니다.
접선 분석은 선택 ground/FOLLOW 구간397개, 신선도/경로 변경 등으로292개 제외하여 해당 필터 내 커버리지57.6%다. 전체 게임플레이 커버리지로 확대하지 않는다.
기능 기록: 최종 유효5/8, 전 마일스톤7/8, 낙하시작9회/착지FOLLOW복귀8회. phase-chain/recovery-generation/terminal-alignment 오류0. 전체 기능 통과 아님. p50/p95/p99 Present·순수CPU·감속 개선율 미측정.

## 4. 원인 분석
확인: 접촉 변위가 실제로 추가 솔버를 호출한다는 수량 경로를 확보했다. 그 비용을 줄이는 접근은 여전히 연구 가치가 있다. 그러나 이번8개체 이동 표본은 경로를 따라 대체로 정상 전진하므로 일괄 접근 감속을 뒷받침하지 않는다.
가설:64개체 밀집 후열의 경우 진행 실패와 압력이 겹칠 수 있다. 이번 단일8개체 결과로64개체 현상을 반증하거나 입증할 수 없다.
미확인: 어떤 후열에서 감속하면 접촉 변위가 줄고 전체 CPU가 줄어드는지. 정렬/진입 대기에 멈춘 앞 개체를 추가 감속해도 이미 낮은 입력이면 이점이 없을 수 있다. MoveTo 인자도 자유 이동 속도 기준으로 보정되지 않았다. 기존 목표 방향 투영의 낮은 값은 우회와 정렬을 포함하므로 그대로 감속 트리거로 사용하지 않는다.

## 5. 검증 수준
관측 모듈 컴파일·기본 거부 계약 진단 성공.8개체 단일 관측 수집 성공. 전체 기능 회귀 실패/미수용. 시각 품질·성능 개선·접근 감속 검증 미실행. 전체 완료 아님.

## 6. 변경 사항
기존 소스/PBO 불변, 별도 nf_ground_progress_observer 모듈과 미션 기록 필드만 추가. 수정 PBO 서명·DSCheckSignatures 검증 성공, 개인키 미포함. 실제 빌드 ID는 공개JSON buildId 참조. 관측 자체의 분기·카운터·파일쓰기 오버헤드는 존재하므로 기존 비용측정과 직접 성능 비교하지 않는다.

## 7. 원시 증거
ANIM-ground-progress-observer-runtime2-contract1, 실패 ANIM-ground-progress-observer-eight1, 실제 관측 ANIM-ground-progress-observer-eight2를 구분한다. observation-analysis.json/workload-context.json/functional-analysis.json과 ground-progress.tsv/gameplay-eight.tsv, plan, server-terminal, client-closed에 연결했다. 원시 로그와 실패 기록은 보존했다. 실제 관측 서버 RequestExit 완료·소유 클라이언트 Alt+F4 종료를 확인했다. 분석/공개화 전 PBO와 증거 해시·JSON 유효성을 검사한다.

## 8. 잔여 문제
감속은 적용하지 않는다. 다음 단일 판단 대상은64개체의 동일 계측으로 지상 후열 저진행과 Displace가 실제로 겹치는지다. 기존8개체 종착 실패5/8을 기능 성공으로 선언하지 않으며, 이를 개별 복구 기능 개발로 확대하지 않는다. 관측 OFF와의 직접 비교 없이는 관측 오버헤드/기존 변동/실제 회귀를 구분할 수 없다.
64개체 관측을 진행한다면 짧은 동일 씬1회로 제한하고 정상 경로 진행은 감속 대상에서 제외한다. 이후에도 낮은 진행/많은 Displace가 겹치는 특정 지상 후열에 한해 국소 default-OFF 감속을 검토한다. 입구 등반 시도·MOTION/FALL/착지·복구에는 대기를 전파하지 않는다. admission-cadence와 혼합하지 않는다.
