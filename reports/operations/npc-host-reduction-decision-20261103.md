# 64개체 최적화 복귀·8파트 호스트 축소 착수 판단

## 1. 작업 목표
64개체 CPU 최적화로 복귀하기 위한 8파트 호스트 축소 착수/기각 판단. 기능 복구 후보는 보존·후순위. 새 구현·게임 실행·회귀시험 없음.

## 2. 실제 수행
기존 팔레트 분할 계획·생성기·과거 표시 실패 결과와 최신 호스트 계획 및 실패 후보 보고서를 읽었다. 새 네이티브 분석·빌드·측정은 하지 않았다. 기존 자료의 재검토이며 독립 반복이 아니다.

## 3. 측정 결과
새 측정 없음: p50/p95/p99, 전체 CPU 절감, 시각 품질 모두 이번 검토에서 미측정.
기존 정적 계획은 weighted bones 224, 61,914 faces(including reverse), 48본 팔레트 예산, 원본11파트에서 overlap_growth 8파트(48/48/48/48/48/48/48/32)를 선정했다. 모든 입력면 정확히1회 할당을 기록한다. 해당 계획 파일 자체의 runtimeVerified=false는 당시 단계의 결과이며 이후 전체 실행 미수행으로 해석하지 않는다.
기존 전체248본 경로는 몸체 일부 누락을 기록했다. 별도 native skin variants에서는 48-bone-per-texture section split만으로도 표시 문제를 해결하지 못했다고 기록했다. 서로 다른 자산·단계의 결과이며 현재 모델의 동일 실패를 입증하지 않는다.

## 4. 원인 분석
확인: 8파트는 기존11파트를 가중치/면 보존 조건으로 재분할한 결과다. 각 호스트의 물리 생성은 기존 network 진단 선행조건으로 기록됐으며 저비용 설계 수용이 아니었다. 물리 생성 제거와 NOCOLLISION 방식은 이미 실패 기록이 있다.
추정: 호스트 감소는 평가·등록·스케줄링 비용을 줄일 수 있다. 전체 CPU 중 독립 기여와 절감률은 미확인.
미확인: 48은 이 도구가 사용한 예산이다. 보편적 엔진 하드 상한이라는 증거는 이번 자료에 없다. 8은 전역 최소라는 증명도 없다. 따라서 단순8→1 통합이 가능하다는 앞선 제안은 근거 부족으로 구현 보류한다. 기존 실패를 모든 통합 방식의 불가능 증명으로 확대하지 않는다.

## 5. 검증 수준

## 6. 변경 사항
게임 코드·PBO·모델·운영 서버·원시 증거 변경 없음. 새 빌드/서명 없음. 이번 체크포인트와 기존 파생 색인만 생성/갱신. 기능 후보를 성능 개선으로 취급하지 않는다. B 공개 미러 게시를 위한 파생본이다. HTTP/해시 검증은 별도 receipt로 판정한다.

## 7. 원시 증거

## 8. 잔여 문제
다음 의사결정은 기존 8파트 분할/부분골격/호스트 비용 결과에서 현재 제약을 넘지 않는 구체적 축소 경계가 있는지다. 현 단계 단순 통합 코딩은 하지 않는다. 이것을 이유로 엔진 전체 재분석이나 새 표시 도구 제작으로 확대하지 않는다. 이미 충분한 제약 근거가 없으면 호스트 축소를 보류하고 기존 물리 질의 소유권 자료에서 동일 결과를 보존하는 작업량 감소 후보를 선정한다.
