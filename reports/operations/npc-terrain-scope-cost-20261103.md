# 지면 FOLLOW 제한·인라인 비용 비교 — 두 후보 미채택

## 1. 작업 목표

전역 지형 후보에서 발생한 비적격 경로의 추가 비용을 줄일 수 있는지 확인한다. 기존 지면 FOLLOW·비전투 상태와 등록 장애물 경계를 빠른 경로의 배제 힌트로 사용한다. 실제 지지 성공을 상태나 경계 정보로 대신하지 않는다.

## 2. 실제 수행

제한 후보는 별도 검사 함수를 호출했다. 지면 FOLLOW가 아니거나 비전투 조건을 만족하지 않으면 원본으로 위임했다. 등록 장애물 경계의 수평1.5m 이내도 원본으로 위임했다.1.5m는 최적화를 끄는 범위이며 충돌·발판 허용 오차가 아니다. 부적격 정보가 없더라도 실제 Overlap·높이·법선·원래 ray fallback을 유지했다.

8조건은 평지, 지붕, 가장자리, lift 거부, 잘못된 지면 힌트, 구조물 옆 지면,18개 경계 정보, FALL 상태다.18개 조건의 추가16개 경계는 합성 메타데이터이며 실제 물체16개를 생성한 시험은 아니다. FALL도 메타데이터 설정이며 실제 낙하 동작 시험이 아니다.

먼저 제한 후보2독립 실행을 분석했다. 비적격3% 기준 미달 후, 검사 함수 호출만 호출부에 넣은 인라인 후보를 별도로 만들고2독립 실행했다. 두 물리 계산 함수·8조건·할당 수명·반환/이유/점 검증·사전5%/3% 기준은 같았다. 각 실행128블록×1000회로128000회이며,2개 후보×2실행의 보고 묶음은512000회다. 현재 후속 작업에서 새로 실행한 것은 인라인2회이고, 제한2회는 앞서 종료된 실행의 최초 분석이다.4회를 한 후보의 반복으로 합치지 않는다.

## 4. 원인 분석

확인: 상태·등록 경계로 원본 위임한 경우에는 추가 Overlap이 실행되지 않았다. 그럼에도 일부 배제 경로의 측정값은3% 기준을 넘었다. 인라인화만으로 사전 기준을 통과하지 못했다.

미확인: 증가분 전체가 검사 함수 호출 때문인지, 스크립트 실행·테스트 래퍼·네이티브 질의 변동·실행 잡음의 어느 부분인지 분리하지 못했다. 서로 다른 프로세스의 자세/실행 조건까지 완전히 같다고 가정해 인라인화의 순수 효과를 계산하지 않는다.

판정: 두 후보 모두 미채택이다. 기준을 완화하거나 좋은 실행만 골라 통과시키지 않는다. 검사 함수 호출 제거가 충분한 해결책이라는 가설은 이번 기준을 충족하지 못했으며, 검사 함수 비용이 전혀 없다고 반증한 것은 아니다.

추가 미확인 경계: 등록되지 않은 물체는 실제 Overlap에서 거부돼도 이전 전역 후보의 추가 비용을 남길 수 있다. 또한 지점별 기존 음성 대조만으로 Overlap 인수와 광선 전체 검사 영역의 포함 관계를 보증하지 않는다. 구현을 게임으로 확대하기 전에 이 인증 범위의 끝점 조건을 확인해야 한다.

## 5. 검증 수준

상태별 위임·기존 물리 함수 보존: 제한 진단 성공. 각 후보2독립 프로세스의 국소 비용 비교: 반복 검증 완료. 비용 선별: 두 후보 모두 미통과.8/64 게임 회귀·시각 품질·전체 성능·최종 수용: 미실행/미완료.

## 6. 변경 사항

격리 미션·계획·분석기와 보고서만 추가했다.4개 완료 실행에서 기존8개 PBO의 해시·서명 검증은 성공했다. 새 PBO·서명·클라이언트·영상은 없다. 원본 Source/PBO·운영 서버·Steam·원시 실패 기록·개인키는 변경하지 않았다.

명령 퇴역·파일 닫힘 마커 후 각 소유 서버를 정리했다. 정상 process quit 인증과는 구분한다. 앞선 사용자 질문 및 대시보드 갱신 중에 끝난 제한2회의 실행 상태를 새 실행으로 기록하지 않았다.

## 7. 원시 증거

제한: terrain-scope-method-cost1/2 및 terrain-scope-method-cost-analysis.json. 인라인: terrain-inline-scope-method-cost1/2 및 terrain-inline-scope-method-cost-analysis.json. 각 plan·실제 mission bytes hash·서명 launch·22열 TSV128행·분석기를 연결한다. 물리 ReferenceExecute/CandidateExecute 원문이 네 실행에서 같은지 다시 대조했다.

공개는 자체 검사 코드·원문/분석 hash·선정 집계이며 전체 원시 로그·게임 설치 자산·PID·명령줄·로컬 경로·키는 공개하지 않는다. 공개 패킷은 전체 실행 자료를 대신하지 않는다.

## 8. 잔여 문제

이번 비교를 끝으로 추가 조건식 미세 수정을 자동 반복하지 않는다. 두 실패 후보와 전역 후보의 실패 판정은 보존한다. 다음 단일 산출물은 실제 솔버 편입 경계·테스트 래퍼 비용 구분·인증 영역 검증을 함께 명시한 구현 가능성 판정이다. 이 판정 없이 게임 PBO를 만들거나8/64 장기 회귀로 확대하지 않는다.

커스텀 전체 CPU 감소와 애니메이션 화면 품질은 여전히 별도 목표다. 바닐라 전체 역공학이나 기능 복구를 최적화의 선행 조건으로 되돌리지 않는다.
