# 호출 내 진입 검사 재사용 격리 후보

## 1. 작업 목표
64개체 진단에서 드러난 접촉·FOLLOW 비용 경로에서, 안전 판정을 바꾸지 않는 호출 내 중복 검사 재사용 후보를 준비한다.
## 2. 실제 수행
현재 TrySupportBypass 전체를 격리 하위 클래스에 복사하고 첫 진입 SupportStepClear 결과만 8방향 비트마스크로 재사용했다. 원본 클래스도 같은 방식으로 복사하여 비교한다. 역치환 시 원본 메서드와 정확히 일치함을 확인했다. 실제 DayZDiag 서버에서 두 클래스 컴파일 후 NPC 스폰 전 종료했다. Python 모델에서216개 반복 입력 비교와65536개 안정 진입/후속 분기 조합을 확인했다.
## 3. 측정 결과
컴파일 성공, 오류 없음, 정상 종료 요청 뒤 종료(-1), 강제 종료 없음. 모델 판정 불일치0. 한 호출의 진입 검사 모델은24→8회이나 이는 물리 호출 실측이나 CPU 절감률이 아니다. 실제 메서드 실행·8/64 기능·p50/p95/p99·화면은 이번 묶음에서 미측정이다.
## 4. 원인 분석
24개 후보는8방향×3거리다. 첫8cm entryStep/entryHeading은 거리와 무관하다. SupportStepClear는Floor/RayCastBullet와SphereCastBullet을 수행하고 이동 명령이나 위치 설정을 하지 않는다. PeerSegmentClear/GroundReservationsClear는 진단 필드 변경이 있으나 월드 위치 변경은 관찰하지 못했다. 엔진 내부 질의 부작용까지 부재가 증명된 것은 아니다. 캐시는 함수 호출 안에서만 존재하며 프레임 사이 결과를 재사용하지 않는다. 기존 Drive→Displace 캐시는 입력 불일치로 기각된 별개 후보다. SupportSweepFast·셀 풀링·Scratch는 반복하지 않았다.
## 5. 검증 수준
컴파일 및 오프라인 논리 진단 성공. 런타임 물리 동등성·기능 회귀·비용 반복 검증·시각 최종수용은 미실행. 후보 채택 안 함.
## 6. 변경 사항
support-entry-reuse1의 원본/후보 클래스, 차이·소스 증명·컴파일 전용 미션만 추가했다. 운영 코드·PBO·실행기는 변경하지 않았다. 신규 PBO 없으므로 서명 대상 없음.
## 7. 원시 증거
ANIM-support-entry-compile1. source-proof.json, offline-proof.json, candidate.diff, compile-only1/terminal.json 및 스크립트 로그. 후보와 원본 SHA를 기록한다.
## 8. 잔여 문제
기존 서버 메서드 하네스로 동일 월드·앵커·목표에서 결과, 선택 경로, 상태 변경의 동등성을 검증한다. 배열 대신 정수 마스크를 사용하지만 분기 비용은 새로 생긴다. 실제 호출 내 검사 절감과 반복 국소 비용5% 이상/대조 경로3% 이상 악화 없음 gate를 확인한 뒤에만8→64 전체 CPU 시험을 검토한다. 국소 통과를 전체 최적화 성공으로 보고하지 않는다.
