# 격자 셀 풀 — 오프라인 검증과 서명 빌드

## 1. 작업 목표
기존 격자 셀 생성만 재사용하는 후보의 입력 순서 보존 가능성을 확인하고 격리 기본OFF 빌드를 준비한다.
## 2. 실제 수행
기존 스냅샷400개와 합성300프레임에서 원본/풀의 ordered pair와 셀 구성원을 비교했다. 독립 전수쌍 oracle로 누락/중복을 검사했다. 합성 조건은 빈군중,음수좌표,밀집,순간이동,사망,8/64/128 크기 변경이다. 첫 분석은 파일 encoding 기본값cp949로 읽다가 실패했으며 출력 전 중단됐다. UTF8 명시로 수정한 성공 분석만 결과로 저장했다. 실제 게임소스는 변경하지 않고 addon의 modded Update 격리 후보를 작성했다. 풀 부분을 역치환하면 기존 Update와 동일함을 확인했다. OFF는 super.Update로 위임한다.
## 3. 측정 결과
오프라인700프레임에서 ordered pair398989건 비교,불일치0. 실자료5문맥 모델 셀생성 합10696→165,합성11210→128. 각 문맥은 별도 풀 초기화다. 이는 모델 생성 수이며 실제 할당량/GC/CPU 속도가 아니다. 신규 게임0,p50/p95/p99 신규 없음. Enforce 실행과8/64 기능·화면 미검증.
## 4. 원인 분석
재사용은 후보쌍/순서를 모델에서 유지했다. 매 프레임 Cells.Clear,이웃 순회,CellKey 문자열,물리검사와 힘 누적은 그대로다. Members.Clear로 이전 내용이 제거된다. 현재 소스검색에서 Crowd.Cells 외부 참조는 발견되지 않았으나 실제 재진입/엔진 배열수명은 미확인이다. pool은 최대 점유셀 수만큼 메모리를 유지한다. 기존 solver Scratch와 범위가 다르며 native Bullet 할당을 줄이지 않는다. 주요CPU 개선 가능성을 증명한 결과가 아니다.
## 5. 검증 수준
오프라인 동등성 진단 통과. CfgConvert config검사·PBO 빌드·서명·서명검증 통과. Enforce컴파일/메서드실행/8→64회귀/반복성능/시각/최종수용 미실행.
## 6. 변경 사항
격리 grid-cell-pool1 소스와 서명PBO만 신규 생성. 기본OFF,현재 실행기·플레이미션·기존PBO·운영서버 미변경. 개인키 신규생성/복사/배포 없음.
## 7. 원시 증거
grid-pool-offline-equivalence.py/JSON,source-equivalence-proof.json,build.json,build.log,signature.log,source 및 PBO 해시를 연결한다. 원시좌표의 기존SHA를 검증했다.
## 8. 잔여 문제
다음은 클라이언트 없는 짧은 실제 서버 메서드 검증이다. 기존 방법시험 하네스를 재사용해 후보 ON/OFF 입력·쌍·힘·속도와 Enforce컴파일을 확인한다. 기능상태 재설계는 하지 않는다. 그 뒤8개체 정상동작을 확인하고 유망할 때만64 비용screen,반복채택gate로 간다. 모델생성감소만으로 긴 회귀나 채택을 정당화하지 않는다. 전체20ms는 목표로 유지한다.
