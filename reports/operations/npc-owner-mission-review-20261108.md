# 8개체 함수 소유자 계측 미션 — 비활성 준비본

## 1. 작업 목표
검증된 EnProfiler 함수 시간·호출수 API를 실제 NPC 미션에 연결할 준비를 마친다. 기존 실행기나 보안 인자를 변경하지 않는다.

## 2. 실제 수행
현재 혼합 미션의 비활성 복사본에만 계측을 연결했다. 8논리/40표시/8수신기, 30게임초 워밍업 후 한 번의 30게임초 계측을 지정했다. CORE+RECURSIVE로 함수별 시간·호출수 상위 60행과 선택된 소유자 5개의 직접 조회를 내보내도록 작성했다. 검증되지 않은 할당 카운터는 제외했다. DIAG 조건부 가드로 일반 서버에서는 계측 API를 실행하지 않는다.

## 3. 측정 결과
새 NPC 실행·컴파일·계측은 0회다. 기존 Commit 코드의 바이트 동일성과 게임 PBO 11개 해시 일치를 확인했다. 이 정적 확인은 런타임 성공의 증거가 아니다.

## 4. 원인 분석
기존 ETW는 실행기 계열과 질의 경계를 부분적으로 보였지만 구체적인 스크립트 호출자를 찾지 못했다. 준비본은 SolveContactsInternal, Drive, Director.Update, Crowd.Update, RunPrePhys의 이름·호출수·원시 시간 조회와 전체 함수 배열을 연결한다. 아직 실제 NPC 데이터는 없고 시간 단위·집계 의미도 미확정이다.

## 5. 검증 수준
비활성 계측 미션과 정적 입력 검증 완료. 컴파일·진단 연결·8/64 기능·시각·성능은 미실행이다. 실제 NPC 비용 소유자를 확인했다고 보고하지 않는다.

## 6. 변경 사항
검토용 미션 복사본·계측 조각·diff·preflight만 추가했다. 실행기·기존 활성 미션·NPC 알고리즘·물리·그래프·게임 PBO·서명·보안 설정은 변경하지 않았다. 새 서명 대상은 없다.

## 7. 원시 증거
preflight.json의 기준/준비 미션 SHA와 11개 PBO SHA, mission.diff, npc-owner-export.c.fragment를 연결한다. 공개본에는 선택된 계측 코드와 경로를 제외한 메타데이터만 제공한다.

## 8. 잔여 문제
기존 공식 진단 서버·진단 클라이언트 실행 경로 정보가 필요해 사용자에게 질문했다. 그 답변 전까지 실행기 수정은 하지 않았다. 앞선 통합 어댑터 생성 명령은 자동 검토에서 실행 전 `blocked by policy`로 거부됐고 구체 이유는 미제공이었다. 같은 명령을 다른 형식으로 재시도하지 않았다. 후속 실행이 가능해지면 8명 연결·함수 출력부터 확인하고, 통과한 경우에만 64명으로 확대한다. 일반 서버 성능 수용과는 별개다.
