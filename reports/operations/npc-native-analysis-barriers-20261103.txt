바이너리·메모리 분석 진단 — 기존 기록 재검토, 새 실험 없음

## 1. 작업 목표

사용자의 바이너리·메모리 분석 진단 질문1~5를 기존 원시 기록과 대조한다. 각 항목을 확인함/추정/모름으로 구분한다. 문서 갱신을 새 게임 실험·후킹·성능 개선으로 기록하지 않는다.

## 3. 측정 결과 — 재사용한 사실

새 NPC 측정0회. Ghidra 첫 초기화 제한900000ms, 후속 설정 기한7200000ms와 실제 도구 경과1029653ms는 서로 다르다. 기한2시간을 실제 분석시간으로 쓰지 않는다. provider는 Ghidra12.1.4, 성공한 함수는 네트워크 resolver이며 분석 파일은16000bytes다.

과거 평가 경계100회에서는 진입 간격 p50 약80ms와 전달 descriptor 약50ms가 관측됐다. 이것은 선택한 과거 경로의 CPU 인자 증거이며 GPU/Present·모든 모드의 최소 간격이 아니다. 별도 하위 프로브 수용0건은 그 함수가 존재하지 않거나 실행되지 않는다는 증거가 아니다.

이번 파일 확인에서 Frida17.23.2 바인딩이 존재했고 복구 기록의 SHA와 일치했다. 현재 MCP 연결 성공이나 현재 attach 가능성까지 시험하지 않았다. 전체 CPU·프레임·8/64·화면 품질 수치는 새로 측정하지 않았다.

## 6. 변경 사항

기존 B 공개 미러에 상세 MD·휴대폰용 TXT·선정 Evidence 투영 JSON과 짧은 README/AI 안내를 연결한다. 현재 상태 JSON·manifest·최신 작업 색인만 같은 근거로 갱신한다. 원시 로그·날짜별 보고서·게임 Source/PBO·운영 서버·Steam·개인키는 변경하지 않는다. 새 빌드·서명은 없다. 게시 성공은 후속 HTTP/해시/스키마 검증으로 따로 판정한다.
