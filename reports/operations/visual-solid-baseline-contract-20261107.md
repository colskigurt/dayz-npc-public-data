# 표시 호스트 후보 대조군 미통과와 시험 판정 정정

## 1. 작업 목표

표시용 추가 호스트 solid 속성만 바꾸는 후보의 최소 기능 비교를 준비하고, 먼저 같은 관측기를 넣은 원래 설정의 8개체를 검증한다.

## 2. 실제 수행

11개 기존 PBO 해시와 격리 미션을 고정했다. 원래 solid=true 설정에서만 실행했다. 후보 setter는 아직 실행하지 않았다. 대조군은 300.024게임초 수집 후 종료했다. 원래 미션·원시 기록은 보존하고, 별도 격리 미션에서 도착 판정만 수정했다. 게임 코드와 PBO 변경은 없다.

## 3. 측정 결과

원래 판정: 낮은 발판8/8, 높은 발판 완료 횟수 조건7/8, 하강/재등반0/8, VALID_TERMINAL0/8. 최종 로그의8개체 모두 high/FOLLOW지만 그 자체를 최종 통과로 인정하지 않는다. ID1은 지지 검증 valid=true 이후 MOTION→FOLLOW SUPPORTED_CONTACT_REPLAN으로 복귀했고 Climbs=1이 남았다. 기존 높은 발판 완료 조건은 Climbs>=2였으므로 다음 단계 진행이 막혔다. 모든40호스트의 관측 애니메이션/물리 콜백은 증가했다. p50/p95/p99·성능·실제 화면 품질은 측정하지 않았다.

## 4. 원인 분석

확인: 후보를 켜지 않은 상태에서도 완료 횟수와 지지 복귀의 불일치가 발생했다. 후보에 의한 기능 회귀라고 분류할 수 없다. 추정: 등반 카운터만 사용하는 시험 단계 조건이 허용된 정상 복구를 도착으로 인정하지 못한다. 미확인: 카운터를 증가시키지 않은 내부 상태의 완전한 의미, 후보 solid 변경의 안전성과 비용 효과. 이 결함을 해결하는 기능 개발로 최적화 작업을 전환하지 않는다.

## 5. 검증 수준

원래 대조군 시험: 미통과, 기록 완료. 읽기용 관측: 성공. 수정된 시험과 후보: 미실행, Enforce 컴파일 미확인. 64개체 확장·반복 성능·최종 수용은 미완료다. 서버는 RequestExit0 후 실제 exit -1이며, 정상 서버 종료 통과로 표시하지 않는다. 클라이언트는 정상 닫기 확인.

## 6. 변경 사항

solid-isolation1 실패 대조군과 미실행 후보를 보존했다. solid-isolation2는 각 단계의 FOLLOW·목표 area·원래 Floor의 새 지지 성공을 요구하고 단계 순서를 유지한다. 최종 ValidSupport 판정도 유지한다. 등반·낙하 횟수는 계속 기록한다. 단순히 high/FOLLOW만 보고 합격시키지 않는다. NPC의 지지·밀침·낙하·착지·추적 로직은 변경하지 않았다. 새 PBO/서명물은 없다.

## 7. 원시 증거

실행 ID ANIM-host-solid-eight-1-off. gameplay-eight.tsv, terminal-state.tsv, visual-solid.tsv, native-state-contract.tsv, 클라이언트 종료 영수증, 고정된 미션·입력 해시를 로컬 증거에 연결했다. 공개 JSON은 요약과 SHA256만 제공하며 절대 경로·개인정보를 제외한다.

## 8. 잔여 문제

다음 단일 산출물은 동일한 수정 시험 판정으로 실행한 8개체 OFF/ON 기능 비교다. 후보는 parts1..4의 solid만 false로 설정하며 대표 파트·바디 존재·레이어·활성·애니메이션 시계·논리 솔버를 보존한다. 실패 시64로 확대하지 않는다. 기능 판정 후에만 외부 CPU/Present 비교를 진행한다. solid=false가 실제 native 접촉 비용을 줄이는지는 아직 모른다.
