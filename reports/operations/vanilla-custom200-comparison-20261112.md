# 바닐라200 대 커스텀200 — 사용자 관찰 비교
작성일: 2026-11-12 KST

## 1. 작업 목표
종료된 두 수동 시험의 서버 부하·갱신 간격·연결 기록을 비교한다. 동일조건 반복 성능 시험이나 순수 애니메이션/물리 비용 분리를 주장하지 않는다.

## 2. 실제 수행
커스텀 MANUAL-single224-200-20261112-launch2와 바닐라 MANUAL-vanilla200-20261112-launch3의200ID 상태·생존·프레임·서버CPU·클라이언트/서버 RPT를 읽고 해시를 검증 시점 기준으로 기록했다.
첫 완전한200ID 스냅샷을 기준으로 각 실행의 초기5~30게임초를 골랐다. 이 구간은 두 실행 모두 첫 사망 이전이다. 원시 스냅샷의200개 고유ID와 행 수를 검증했다. 바닐라 미션 시간은 절대Age, 커스텀은 spawn이후Age이므로 직접 같은 원시초를 비교하지 않았다.
바닐라 미션 초기 좌표식/override인자 컴파일 실패 두 실행은 보존하고 성능 비교에서 제외했다. 최종 실행은 커스텀모드0/바닐라 native AI, M4A1 자동사격·30발탄창·예비15개·추가탄약6묶음을 확인했다. AI/물리/애니메이션 코드는 수정하지 않았다.

## 4. 동기화 및 원인 분석
사용자는 커스텀 실행에서 화면은 괜찮으나 동기화 이상을 보고했다. 바닐라의 서버timeslice 분포는 이번 관찰에서 훨씬 짧고 안정적이었다.
한정된 RPT 패턴 감사: 커스텀 양쪽0건, 바닐라 클라이언트0건/서버1건. 바닐라 netcrypt timeout15:07:39.977은 로그아웃15:07:34.458 이후다. 이1건을 플레이 중 손실로 판정하지 않았다.
원시 script의 SCRIPT(E)/NULL pointer/Exception/명시미션실패 패턴은 최종 두실행 모두0이었다.
미측정: packetloss/RTT/대역폭/serialization시간/서버발신빈도/client보간·프레임 분위수/함수별CPU self-time. 로그상 오류 부재는 네트워크 완전정상 증명이 아니다.
추론: 화면 프레임보다 커스텀 서버 측 계산·갱신 지연이 이번 동기화 문제의 유력 원인이다. 어느 함수가 지배적인지는 이 시험만으로 확정할 수 없다.

## 6. 변경 사항 및 종료
분석 스크립트/JSON/보고서만 추가. 커스텀 원본·PBO·키·Unity 작업 무변경. 바닐라에는 별도 디버그 미션/프로필만 사용했으며 PBO 빌드·서명 대상 없음.
두 게임·서버는 실제 프로세스 부재 확인. 두서버 로그에 종료요청0이 있으나 실제 retained exit는-1/forcedfalse. 정상exit0로 보고하지 않는다.
