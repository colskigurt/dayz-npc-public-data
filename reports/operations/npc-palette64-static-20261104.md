# 8→5파트 무손실 재분할 후보

## 1. 작업 목표

기존 부분 골격·동결 포즈·호스트 연구의 중복을 확인하고, 64개체 전체 CPU 작업량을 줄일 수 있는 lossless 자산 재분할 후보를 선정한다. 정상 밀침·낙하·착지·FOLLOW·재등반 솔버는 변경하지 않는다.

## 2. 실제 수행

기존1/8/64 자원·비용 비교, scale optimization review, 48본 분할 계획과 전체 native skin 실패 변형을 읽었다. 부분 골격 535본은 이미 구현됐으며 새로 도입한 것으로 보고하지 않는다. static/animated 대조에는 motor/DisableSimulation 영향이 있어 순수 애니메이션 비용을 추출하지 않았다.

기존11 MLOD 원본 해시를 모두 기존 계획과 대조했다. 원래 분할기의 결정적 휴리스틱을48/64/96본 예산으로 계산했으며48본에서 기존8파트를 재현했다. 실제 자산 후보는 최소 확장인64본5파트만 생성했다. 기존 semantic-face multiset·재파싱 검증기를 재사용해 바이트로 인코딩된 가중치·좌표 flags·노멀·UV·재질·Memory 본 좌표를 대조했다. Blender·Workbench·클라이언트·서버 실행은 없고 원본 자산은 읽기만 했다.

## 3. 측정 결과

## 4. 원인 분석

확인: 기존 분할기의48은 하드코딩된 예산이며 이 자료만으로 엔진의 최대치를 뜻하지 않는다. 이 값이8파트 구성에 영향을 줬다. 64예산에서도 면/가중치 삭제 없이5파트 구성이 가능하다. 요구 본 포함 기존535 합계 재현으로 계산 기준도 맞췄다.

가설: 호스트 생성·명령/그래프·pose dispatch·프레임 transform 쓰기 수와 중복 본 평가를 줄일 수 있다. 미확인: 그것이 현재 CPU 병목 중 얼마나 차지하는지, 더 큰 팔레트가 올바르게 스키닝되는지다. 바닐라95본 골격 존재를64 weighted palette 지원의 증명으로 사용하지 않는다. 과거 전체248본·48본 section split 표시 실패는 해당 자산 단계의 증거이며 이번5파트의 성공/실패를 미리 증명하지 않는다.

## 5. 검증 수준

정적 분할 및 자산 의미 roundtrip: 진단 성공. 런타임·기능 회귀·시각·성능·반복 최종 수용: 미실행. 기존 게임을 교체하거나8→5 적용 완료로 보고하지 않는다. 20ms p95 미달성.

## 6. 변경 사항

기존 research 아래 palette-budget-review-20261104의 plan/analysis/decision 및 private-palette64-candidate만 추가했다. 기존 원본 MLOD·애니메이션·PBO·서버·Workshop·개인키는 변경하지 않았다. 새 PBO가 없어 신규 서명 대상은 없으며 서명 완료로 보고하지 않는다. 생성 model.cfg/vehicles fragment는 초기 flat palette 진단 입력으로, 현행5파트 native binding이나 hit geometry 통합 완료본이 아니다.

## 7. 원시 증거

실행 ID는 정적 작업 palette-budget-review-20261104다. analysis/64 plan/candidate.json/5개 MLOD 및 사용한 두 래퍼와 기존 scope/skin-variant 보고서를 해시와 연결한다. 공개는 집계·입력해시·검증 조건·예상 분기만 포함한다. 원본 모델·클립·로컬 절대경로·프로세스·키는 공개하지 않는다. 전체11 MLOD 원본 해시는 기존 plan과 일치했다.

## 8. 잔여 문제

다음 단일 산출물: 새64 weighted palette 파트 하나의 native 컴파일·실제 스키닝 go/no-go. 먼저 단일 파트만 기존 native 입력/리그와 대조하고 실패하면 전체70클립 변환·5파트 gameplay 작업을 시작하지 않는다. 컴파일만 성공하면 표시 성공으로 처리하지 않는다. 표시·포즈 계약이 통과해야5파트 전체와 동일 조건 비용 비교로 넘어간다.

후보 위험은 native palette/본 매핑, 파트 경계 seam, root·접촉 본 일치, 복제·피격 geometry다. 기존8파트 baseline을 보존한다. 기존 기능 구현을 새로 설계하거나 실패한 parent/physics 해제 변형을 재시도하지 않는다. 실제 CPU 이득이 반복 검증되지 않으면 승격하지 않는다.
