# 피해 수신기 축소 골격 — 8개체 이동 비교 통과, 비용 미측정

## 1. 작업 목표

전용 피해 수신기250→27노드 후보가 기존8개체 고저차 추적·등반·하강·낙하 복귀·재등반을 보존하는지 동일 시나리오로 비교한다. 실제 골격 구분도 런타임에서 확인한다. CPU/표시 품질/실제 무기 피격과 이동 기능을 별도 판정한다.

## 2. 실제 수행

기존 lane-eight OFF 시나리오와 고정된 상태 계약 분석기를 재사용했다. 수신기는 CombatEnabled=true로 생성된다. 먼저 공격도 켠 대조군을 실행했으나 원래 공격 OFF 이동 조건과 달라져300초에1/8만 완료했다. 실패 원문을 보존하고 축소 후보에 귀속하지 않았다. 이 공격 활성화 조건의 후보 실행은 하지 않았다.

기존 DGNativeInteractionProbe의 생성 후 Director.CombatEnabled=false 패턴을 양쪽에 동일 적용했다. 수신기·피격/사망 콜백은 유지하고 선제 공격만 끈다. 시나리오의 자극·지형·4단계·종착 기준은 변경하지 않았다. 수신기도 종료 시 native retirement를 거치도록 하네스에 포함했다. 모든 로딩 PBO 서명을 재검증했다.

## 4. 원인 분석

확인: 런타임 수신기 mesh 경로와 Jaw/spine2 lookup으로 전체/축소 골격을 구분했다.14클립 보존 본 포즈 비교에 이어 실제8개체 이동에서도 후보 기능 관문을 통과했다.

확인: 공격 활성화 대조군의 실패는 후보 적용 이전에 발생했다. 공격 OFF 대조군은 단일 실행에서8/8로 통과했다. 이 차이가 모든 실패의 단독 원인이라는 반복 검증은 하지 않았다. 고지대 공격/이동 상호작용 결함은 별도 보존하며 이번 최적화를 기능 복구 작업으로 바꾸지 않는다.

미확인: 실제 총기·근접 피격 헐·사망 처리와64비용. 기존 자동 실무기 bridge는 IsMultiplayer()에서 명시적으로 거부한다. 해당 조건을 제거하거나 직접 피해 주입으로 실제 무기 시험을 대신하지 않았다. 과거 오프라인 총기 시험은 Torso에서 Head로 오인된 미합격 기록이 있어 전체 성공 근거로 재사용하지 않는다.

## 5. 검증 수준

8개체 이동 회귀 단일 비교 쌍 통과.14클립 보존 본 포즈·설정 통과는 이전 별도 실행 근거다. 반복 기능 검증·실제 피격/사망·64기능·반복 비용·시각 품질 및 최종 후보 수용은 미완료다. 서버 종료 요청/retirement 완료 후 실제 종료코드-1이며 정상 종료 수용은 아니다. 클라이언트·BE·서버 종료를 확인했다.
