# 피해 수신기 골격 축소 후보 — 런타임 생성 실패 진단

## 1. 작업 목표

표시5파트와 정상 밀침·낙하·착지·FOLLOW·재등반을 보존하면서, 별도 피해 수신기의 골격250→27노드 축소 후보를 런타임 검증하려 했다. 본 수 비율을 CPU 절감률로 취급하지 않는다.

## 2. 실제 수행

14클립을 한 연결에서 전체/축소 수신기 한 쌍씩 비교하는 격리 하네스를 준비했다. 초기 Enforce 식별자/override 인자 오류를 수정했다. v1의 기존 클래스 상속 누락에 따른 simulation 오류를 수정하고, v2의 골격 등록 누락을 외부 Anims/cfg XML로 보완했다. 과거 파일과 실행 디렉터리는 보존했다.

등록 후 pose5는 전체 골격 참조 객체 CreateObjectEx에서 네이티브 크래시했다. pose6은 시험 그래프의 존재하지 않는 기본 노드 HordeController를 Review_0로 수정했지만 동일 생성 위치에서 크래시했다. pose7은 기존 네트워크 파트처럼 28개 시험 객체와 대응 Type 클래스를 명시했지만 동일 크래시했다. 두 변경 모두 단독 해결책으로 확인되지 않았다. 생성 실패 후 클라이언트는 정상 종료했고 서버는 자체 크래시로 종료했다. 강제 정상 종료로 기록하지 않았다.

## 3. 측정 결과

pose3~7 모두 포즈 표본0건. pose3은 factory/script 실패이며 cleanup이 끝나지 않아 소유 서버를 강제 종료했다. pose4~7은 서버 접근 위반 종료(-1073741819)다. pose5~7의 크래시는 원래 전체 골격을 사용하는 참조 객체 생성 중이며 축소 후보 객체 생성까지 도달하지 않았다. 8/64 기능, p50/p95/p99, CPU, 실제 표시 품질 및 실제 피격 헐은 측정하지 못했다. 서명 검증은 새 PBO별 성공했지만 런타임 성공을 의미하지 않는다.

## 4. 원인 분석

확인: initial class patch 상속 문제와 외부 골격 등록 누락은 각각 실제 로그로 확인했다. 후속 등록본은 같은 missing-skeleton 오류가 없으나 전체 참조 생성에서 네이티브 접근 위반이 남았다.

반증 범위: 그래프 기본 노드 수정만으로 해결된다는 가설과 객체/Type 선언 추가만으로 해결된다는 가설은 이번 조건에서 성립하지 않았다. 이 설정들이 모든 경로에서 무관하다는 증명은 아니다.

모름: 네이티브 생성자에서 어떤 포인터/리소스가 유효하지 않은지, 후보 골격이 실제 포즈/피격에 맞는지, 평가 비용이 줄어드는지. 전체 참조 생성 실패를 축소 골격의 기능 실패로 귀속할 수 없다.

## 5. 검증 수준

정적/네이티브 변환/빌드·서명 진단 성공. 시험 객체 런타임 생성 실패. 포즈 회귀 미실행, 8/64 기능 회귀 미실행, 반복 비용 검증 미실행, 실제 표시 및 최종 수용 미완료. 현재 후보는 미수용·운영 미적용이다.

## 6. 변경 사항

격리 receiver-skeleton-review1 아래 build2/build3, fixture2/fixture3와 pose1~7만 생성했다. 기존 게임플레이 PBO·원본 클립·충돌/지지 솔버·네이티브 시계·운영 서버를 변경하지 않았다. 최신 fixture3 SHA256은 85CD0BC68286F8FF7B0B0DC0EDD7E42624FD5340EBCC4B4BC2A57E574792177E. subset PBO는 74718EE7AE304669BD5A77E8534C324C15250D2E0A882B89C642F6ABE34526E8. 둘 다 서명 검증 성공. 외부 골격 XML은 별도 SHA256으로 고정했다. 개인 키를 출력물에 포함하지 않았다.

## 7. 원시 증거

ANIM-receiver-pose14-3~7의 manifest/staged-plan, 종료 receipt, script 및 crash 로그를 해시 검증하고 보존했다. pose6/7 analysis.json은 표본0·RUNTIME_POSE_GATE_NOT_PASSED를 기록한다. 시험은 동시 최대2객체, AI/이동 비활성, 동일14클립 비교 의도였지만 첫 참조 생성에서 중단됐다. 성능 비교의 반복 실행으로 세지 않는다.

## 8. 잔여 문제

같은 구조의 재실행을 더 늘리기 전에, 이미 성공한 수신기 생성 경로와 이번 전체 참조 클래스의 초기화 입력/실제 설정 차이를 좁혀야 한다. 생성이 통과하면 full/subset 구분, 27본 포즈/피격점/6구역 설정을 검증하고 실제 피격·사망 포함8개체 회귀 후64 비용 반복 비교로 진행한다. 생성 결함을 지지·등반 기능 개발로 확대하지 않는다. 후보의 CPU 절감·시각 개선·20ms p95 달성은 주장하지 않는다.
