# 64개체 반복 계측 — 표시 경로 차이 발견

## 1. 작업 목표

전투ON64 혼합 장면 기준선의 반복성을 확인한다. NPC 알고리즘과 PBO를 변경하지 않는다.

## 2. 실제 수행

동일 엔진·11PBO·미션 해시, 동일64/320표시+64피해수신기, 고정 카메라·10초씩 지면/낮은/높은 목표·30초 수집을 재사용했다. 추가1회 수집과 전체 구간 검증을 완료했다. 준비된 세 번째 실행은 시작하지 않았다.

## 3. 측정 결과

| 항목 | 기존 기준선 | 추가 반복 |
|---|---:|---:|
| Present p95 ms |18.4789|16.963665|
| 화면 변경 p95 ms |19.3519|20.06173|
| 서버CPU ms/게임초 |821.6193|826.8824|
| 생존/인식/2m이동 |64/64|64/64|
| Present 모드 |Hardware: Independent Flip|Composed: Flip|
| AllowsTearing |1|0|

두 실행 모두 SyncInterval0이지만 표시 경로는 다르다. 추가 실행은 Present2868표본/화면변경1495표본이며 화면 변경 간격이 약20ms에 모인다. 추가 실행에서 공격시작48/피해적용37, 수신기 위치차0m, 전체 표시/수신기 콜백 증가를 확인했다.

## 4. 원인 분석

확인됨: Present 모드와 tearing 허용 상태가 실행 사이 달라졌다. 평균 FPS나 Present p95만으로 실제 표시 품질을 판단할 수 없다. 모드 변경 원인은 미확인이다. 합성기/창 상태를 후보로 볼 수 있으나 근거 없이 원인으로 확정하지 않는다. NPC/물리 최적화 개선률을 계산하지 않는다.

## 5. 검증 수준

추가 수집과 단일 구간 인구·호스트·전경·CPU 정렬 검증 성공. 동일 표시 조건의 반복 검증 완료는 아님. 기능 전체/시각 품질/성능 개선 수용은 미완료. 서버는 RequestExit0 후 실제exit−1, 클라이언트는 정상 닫기 확인. 세 번째 시험을 기다리던 수집기는 첫 캡처 종료와 두 번째 요청 부재를 확인한 뒤 취소했다.

## 6. 변경 사항

기존 수집기와5개 보조 스크립트를 그대로 재사용했다. 분석기는 case/output 인덱스만 추가하고 기존 검증 조건을 유지했다. 게임 PBO·NPC 코드·애니메이션 변경 및 새 서명 대상 없음.

## 7. 원시 증거

실행 ANIM-mixed-gameplay64-repeat2. analysis-0.json, presentation-comparison.json, present.csv, server-process-cpu.csv/json, gameplay-eight/mixed-hosts/part-command-clock/server-frame/visual-app TSV를 보존했다. 공개본에는 집계만 제공한다.

## 8. 잔여 문제

세 번째 반복 전에 표시 모드가 달라지는 조건을 좁히고 같은 모드의 비교를 확보한다. 의도적으로 실패 자료를 제외하거나 두 실행 프레임을 합쳐20ms 수용으로 만들지 않는다. 정상 낙하·접촉·재등반과 실제 화면 품질은 별도 판정한다.
