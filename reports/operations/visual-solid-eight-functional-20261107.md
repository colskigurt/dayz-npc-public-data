# 표시 호스트 solid 후보 8개체 단일 기능 비교

## 1. 작업 목표

표시용 추가4파트의 solid만 false로 바꾸는 후보가8개체 지지·추적·등반·하강·재등반을 보존하는지 동일 미션 OFF/ON으로 비교한다.

## 2. 실제 수행

기존11개 PBO와 같은 수정 미션을 사용했다. 대조군은 원래 solid=true, 후보는 서버 표시 파트1..4만 false로 설정했다. 레이어·대표 파트·바디 존재·활성/동적 상태·그래프·논리 지지/밀침/낙하 솔버는 유지했다. 이전 NOCOLLISION 실패 후보를 반복하지 않았다. 양쪽은 전투 OFF·8개체·40호스트 조건이다.

## 3. 측정 결과

대조군75.5281게임초, 후보72.8356게임초에 각각8/8 유효 최종 상태. 낮은/높은 발판, 하강 후 지면 복귀, 낮은 발판 재등반의 단계 순서와 마지막 실제 지지 검사 통과. 모든40호스트 콜백 증가. 후보 추가32파트 solid=false, 대표8파트 true, 관측 레이어는 전부524288 유지. 완료 시간 차이는 CPU 절감 증거가 아니다. p50/p95/p99·CPU·GPU·실제 화면 품질은 미측정이다. 낙하 전이와 완결된 FALL→LAND→FOLLOW 수는 공개 JSON에 원래 전이 정의로 기록한다.

## 4. 원인 분석

확인: 이 단일8개체 실행에서는 레이어를 바꾸지 않은 solid 후보가 바디·위치 가드와 이동 단계 계약을 유지했다. 미확인: 실제 접촉 수/비용 감소, 클라이언트 solid 복제, 전투·피격·사망/시체와의 상호작용,64개체의 비용·안정성. solid getter 변화와 성능 개선을 동일시하지 않는다. 이전 레이어 후보 실패 원인이 해결됐다는 주장도 하지 않는다.

## 5. 검증 수준

Enforce 컴파일 및 단일8개체 기능 비교 통과. 반복 검증·64개체·시각 품질·전투/최종 수용은 미완료. 클라이언트 정상 닫기 확인. 양쪽 서버 RequestExit0 이후 실제 exit -1, 강제 종료 없음이며 정상 서버 프로세스 종료 판정은 실패/미통과다.

## 6. 변경 사항

격리 미션의 opt-in solid setter와 대칭 관측기, 단계별 실제 지지 도착 판정만 사용했다. 앞선300초 대조군 미통과 기록은 보존했다. 게임 소스·배포 PBO·애니메이션 자산/시계는 변경하지 않았다. 새 PBO나 서명 대상 없음. 후보는 기본 구현으로 채택하지 않았다.

## 7. 원시 증거

ANIM-host-solid-supported-eight-1-off 및2-on. analysis.json, gameplay-eight.tsv, visual-solid.tsv, terminal-state.tsv, native-state-contract.tsv, client-closed.json, 사전validation-contract를 SHA256으로 연결했다. 공개 JSON에는 원시 개인 식별자·절대경로·프로세스 정보를 제외했다.

## 8. 잔여 문제

다음 단일 산출물은 동일 평지64개체 OFF/ON의 외부 CPU·Present 선별 비교다. 비용 감소가 없으면 이 후보를 확대하지 않는다. 선별 기준은 서버CPU3%이상 감소/Present p95악화5%이내이며 통과하더라도 독립3쌍과64개체 기능·전투 검증 전 수용하지 않는다. 전역20ms목표는 미달성/미검증 상태를 유지한다.
