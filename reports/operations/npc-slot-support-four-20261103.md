## 1. 작업 목표

기존 조건부 지지 검사 후보의64명 OFF→ON→OFF→ON 비교를 끝내고, 유효성·기능·서버 시간의 반복성을 판정한다. 실패한 착지 사례는 기존 연구와 대조한 뒤 작은 공간 시험으로 거부 위치를 좁힌다. 정상 밀침·낙하·착지·FOLLOW·재등반을 유지하며64명 동시 지붕 점유를 요구하지 않는다.

## 2. 실제 수행

동일10개 서명PBO·미션·입력·카메라·FPS cap을 고정해4실행을 완료했다. 각 실행 전 실제 DayZ 화면을 확인하고20초 대기했다. 바뀐 게임 조건은 support-context-fast.flag다. 원시 상태 계약·지원 사용·서버 틱·명령시간을 종료 후 분석했다. 첫 쌍을 다시 분석한 것을 새 반복으로 세지 않는다.

ON1의24번 FALL 사례를 이전 ID24 복구 볼륨 연구와 대조했다. 기존 포즈 대응 복구는 FOLLOW·특정 포즈와 상태에만 적격이고 이번 FALL은 해당하지 않는다. 기록된 최종 위치와 같은 fixture를 기존 하네스에서 구성하고20초 기다린 뒤 원래 LandingSpace와 그 하위 공간 검사를10지점에 호출했다. 같은7개 서명 패키지를 재사용했고 게임플레이 소스/PBO를 수정하지 않았다. 게임 창 없는 서버 공간 진단이며 애니메이션 품질 시험이 아니다.

## 4. 원인 분석

확인: 검사 수를 줄여도 이번64명 서버 시간이나 기능이 일관되게 좋아지지 않았다. 후보ON만 문제인 상태도 아니며 OFF 두 실행도 실패한다. 군집 궤적 차이와 명령시간 저하가 있어 단순 p95 차를 특정 함수 self-time으로 귀속하지 않는다.

ON1의24번은95.804초 지지 상실 FALL 뒤280.078초까지 LAND가 없었다. 기록된 최종 위치의 원래 착지 검사를 새 공간 진단에서도 FOOT_X_SUPPORT가 거부했다. 이는 기존의 FOLLOW 고정 몸통 겹침 진단과 구분되는 실제 거부 단계다. 공간 진단은 주변 군집·시간에 따른 포즈를 재현하지 않았으므로 원래 동적 실행의 모든 프레임이 같은 이유였다고 주장하지 않는다.

가설: 현재 위치에서 발판 검사에 막힌 상태와, 바닥을 요구하는 측면 복구 경로 사이에 계약 간극이 있을 수 있다. 근처10cm endpoint 통과는 탈출 경로의 존재 증명이 아니다. Floor 내부의 ray hit normal/fraction을 이번 로그에 따로 남기지 않아 FOOT_X_SUPPORT 안의 세부 거부 조건은 미확정이다. 몸통 구 접촉false도 완전한 물리 비침투 증거가 아니다.

효과 부족/보류: 빠른 지지 검사의 광선 생략을 최적화 성공으로 수용하지 않는다. 기존 방향 추가·걸음 축소의 과거 실패를 반복 해결책으로 제시하지 않는다. 지지true 강제·충돌 삭제·반경 축소·타임아웃 완화는 적용하지 않았다.

## 6. 변경 사항

게임 코드/PBO 변경은 없다. 기존10개 패키지의 각64명 실행 전 서명/해시 재검증 성공, 공간 진단은 기존7개 서명/해시 검증 성공이다. 새 서명 대상은 없다. 별도 분석·작은 진단 미션·기록과 공개 집계를 추가했다. 원본 자산·운영 서버·Steam·개인키는 변경하지 않았다.

준비 오류도 보존했다. 공간query1은 ORIGIN 문자열 치환이 ORIGINAL_LANDING 라벨까지 바꿨고 배치가 반복 실행돼 파일이 마지막 배치로 덮어써졌다. query2는 부정확한 escape 가정의 준비assert가 실패했으며 불완전 설정은 런처 가드로 종료됐다. 원시 분리자는 확인 결과 실제tab이었다. query3은 라벨과 파일 기반1회 가드만 수정했고 READY/DONE 각1회·110행을 검증했다. 준비 실패·반복 마커를 독립 반복으로 합산하지 않는다. 기존 원시 파일은 보존했다.

## 8. 잔여 문제

빠른 지지 검사는 기본OFF·미채택으로 유지한다. 다음 가장 가치 있는 국소 산출물은 캡처된 FALL 포즈에서 기존 PressureSlide/PressureEscapeStepClear가 가까운 안전 착지점까지 이동하지 못하는 이유와, 기존 검사로 연결 가능한 swept 경로가 있는지에 대한 판정이다. 기존 벽/가장자리 실패 입력을 음성 대조로 함께 사용한다.

새 후보가 필요하면 구현 전에 적격 상태·물리 안전 계약·예상 비용·위험을 별도로 제시한다. endpoint만 통과하면 채택하지 않고 실제 이동 인계와 낙하/재등반을 검증한 뒤8→64로 확장한다. 실패하면 안전 판정을 완화하지 않고 해당 후보를 보류한다. 단지 같은64시험을 반복하거나 애니메이션 시계를 추측으로 바꾸지 않는다. 실제 표시 품질과Present 비용은 별도 목표로 유지한다.
