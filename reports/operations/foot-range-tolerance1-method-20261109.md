## 1. 작업 목표
사용자 “허용으로 진행할게”에 따라 별도 후보에서 발 지지 lift 차이 최대1mm를 허용한다. 기존1e−5m 실패 기록은 보존하고,0.25m 수용/거부 판정은 여전히 동일해야 한다. 실제 질의 비용 선별이 통과할 때만8→64로 확대한다.

## 2. 실제 수행
기존 engine1 미션과14개 입력PBO를 재사용했다. 기존2610조건·동일 길이축소 kernel은 그대로 두고 별도 미션의 오차 기준만1e−5→1e−3m로 변경했다. 잘못된 milliseconds 헤더를 profilerRawUnits로 정정했으며 측정 API 설정은 유지했다. 실제 지형·컨테이너 fixture, 반경0.05/0.14/0.2m를 비교했다. 양쪽 동일 warmup 뒤1000회 발 kernel(5000Ray)씩12batch를ABBA 순서로 측정했다. 새 NPC/클라이언트/PBO는 없다.
시작 전 trial-contract에 중앙 개선5% 이상 및6쌍 모두 개선을 명시했다. 결과 확인 후 문턱/순서/표본 제외를 바꾸지 않았다. user1mm 허용은 모든 기능 차이를 허용하거나 과거 실패를 통과로 바꾸라는 지시로 확대하지 않았다.

## 4. 원인 분석
확인: 새 허용기준 아래 이 표본의 수치/수용 판정 gate는 통과했다. 비용은 일부 쌍에서 줄었으나 한 쌍에서 증가했고 중앙도5%에 못 미쳤다. 특정 느린batch를 이상치로 제외하거나 추가 실행으로 좋은 결과를 고르지 않는다.
미확인: 한 쌍 증가의 원인이 스케줄링·캐시·물리 질의 내용 중 무엇인지, 줄인 광선 길이가 총CPU에 유효한 기여를 하는지, 반복 운동에서1mm 차이가 누적되는지. raw profiler 값을 순수 물리 질의 시간 또는 전체 절감률로 해석하지 않는다.
따라서1mm 허용이 이 후보의 성능 채택을 정당화하지 않는다. query수는 여전히10회/solve에 해당하며 이번은 한 발 kernel 선별일 뿐이다.
