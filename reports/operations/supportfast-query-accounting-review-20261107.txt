# SupportFast 질의 회계 검토: 실제 비용 감소는 미입증

## 1. 작업 목표
추가 실행 없이 SupportFast의 광선 감소를 전체 계산량 감소와 구분하고, 기존 연구와 중복되는 후속 제안을 배제한다.

## 2. 실제 수행
검증된3실행의 support/gameplay 카운터를 동일 관측 구간으로 결합했다. 각 구간의 실제 solve 수와 광선 수에 대해 footRays=10×solves−skipped를 확인했다. StructureSupportBound의 소스와 과거 동결 포즈 실험 support-frozen-cost-20261031-1603을 재사용했다. 게임/PBO/기존 원시 로그를 변경하지 않았다.

## 3. 측정 결과
재분석은 새 독립 반복0회다. 대조군:15.737게임초,45,220solves,발 광선452,200,관절sweep180,827. 후보:15.5253게임초,45,597solves,발 광선186,338,관절sweep182,368,추가 지지sweep은67,408~71,183회 범위다. 주요 세 질의 계열의 게임초당 합계는 대조40,225.39회에서 후보28,090.54~28,333.69회로29.56~30.17% 감소 범위다. 이는 모든 엔진/스크립트 질의 수가 아니다. 전체CPU의 독립 원인이나 절감률도 아니다. solve빈도는2,873.48→2,936.95회/게임초로 약2.21% 증가했다. p50/p95/p99는 이전 실행의 값을 유지하며 새로 측정하지 않았다.

## 4. 원인 분석
확인:successful fast 사용마다 추가SphereCast가 최소1회 있고, attempts마다 최대1회다. sweeps는 직접 로그에 없으므로 정확한 수를 복원할 수 없다. 사용 실패 후 추가광선 fallback까지 할 수 있다. jointSweeps는 이 지지sweep을 포함하지 않는다. 발 광선58% 감소를 총 물리비용58% 감소로 해석하는 가설은 부적절하다. 주요 질의 합계 자체도 감소했으나 첫쌍 CPU는 증가했으므로 단순 호출 수만으로 원인을 설명할 수 없다. 구엔진 동결포즈 연구에서도 low1foot 적용은 약1.06~4.52%, high2foot은 약20.51~22.14% 메서드 경과시간 감소였다. 캐시가 따뜻한 정지포즈이고 현행 동적64개체 비용으로 전이할 수 없다.

## 5. 검증 수준
오프라인 카운터 정합성 진단 성공. 성능 개선·시각 품질·최종 수용 아님. 기존 첫쌍은 미수용,3쌍 비교 미완료. 외부게임 동시부하 여부는 이전 보고서의 미확인 판정을 유지한다.

## 6. 변경 사항
새로운 파생 JSON과 보고서만 추가. PBO0개,게임코드 변경0개,새로운 서명 없음. 원본 및 기존 서명본 보존. 사용한 코드 해시를 하단에 연결한다. 이 분석을 계기로 추가 지지sweep이나 Drive/Displace의 권위 있는 중간 경로 검사를 삭제하지 않는다.

## 7. 원시 증거
원래 실행 ANIM-sf262b-cost-1-control/2-candidate/3-candidate의 support-context-use.tsv/gameplay-eight.tsv와 analysis1~3을 사용했다. 신규 query-accounting-review.json에 입력 해시와 과거 실험을 연결했다. 동일 실행의 재분석을 새로운 반복으로 세지 않는다. 내부 체크포인트에서12개 입력 파일을 검증했다. 체크포인트 해시는 공개 JSON에 연결하며 내부 원시 파일은 공개하지 않는다.

## 8. 잔여 문제
기존 Drive→Displace 단일 종점 병합은 중간Contacts/Lift·swept path·부분성공rollback을 바꿔 기각된 제안이므로 반복하지 않는다. zero delta만으로 지지/관절 검사를 생략할 근거도 없다. 현재 후보는OFF 유지한다. 다음 수정 판단에는 전용 조건의 남은 비용 비교 또는 현재5파트 물리질의/호스트 비용을 구분하는 기존 프로파일 근거가 필요하다. 추가 측정은 이 결정에 기여할 때만 진행한다. 새 알고리즘을 근거 없이 적용하지 않는다.
