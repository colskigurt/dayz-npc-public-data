# 피해 수신기 전용 축소 골격 후보 — 변환·빌드 완료, 런타임 미검증

## 1. 작업 목표

서버 셀 재사용과 별개로, 생존64개체의 피해 수신기 애니메이션 계산 자체를 줄일 후보를 검토·준비한다. 기존 표시5파트·지지/접촉·정상 밀침·낙하·착지·추적·재등반과 피해 정책을 유지하는 것이 조건이다.

## 2. 실제 수행

기존 코드·수신기 제작 도구·MLOD·원본TXO 및 이전8파트 축소 입력을 조사했다. 현행 PBO의 command/combat 소스는 원문과 바이트 일치했고, 수신기 소스 MLOD 해시는 기존 제작 기록과 일치했다. 패키지 모델은 ODOL이므로 MLOD와 바이트 동일하다고 주장하지 않았다.

피격 LOD의 가중 본, 공개 스크립트가 쓰는 본, 보수적 추가 본과 모든 부모 연결을 유지한27노드 후보를 별도 폴더에 만들었다. 14클립의 키·부모·타이밍 헤더를 보존했고 Memory LOD만248→25점으로 줄였다. 다른4개 LOD는 원문 바이트를 유지했다. Workbench 기존 실행기·RegisterResourceFile API로 골격1/클립14를 한 번에 변환하고 기존 감사 방식으로 재검사했다. 별도 데이터 PBO를 빌드·서명·검증했다. 비교용 전체 골격 참조 클래스도 포함했다. 게임 실행 및 운영 배포는 하지 않았다.

## 4. 원인 분석

확인: 원본 수신기는 전체 골격을 참조하지만 authored FireGeometry/HitPoints에서 실제 가중한 본은11개다. 추가 보호 본 및 부모를 보존하면 후보27노드가 된다. 이전8파트 축소 manifest는 표시8파트/총535 retained render bones를 다뤘고 수신기를 포함하지 않았다. 조사한 자료에서 이 전용 수신기 후보의 실제 비용 시험은 찾지 못했다. 과거 부분 골격의 효과 부족을 이번 후보 성공 근거로 바꾸지 않는다.

추정: 사용하지 않는 수신기 골격 채널을 줄이면 평가·메모리 비용을 줄일 가능성이 있다. 비용의 어느 비율이 본 수에 비례하는지, 네이티브 내부가 이미 생략하는지는 모른다. 250→27 비율을 성능 절감률로 제시하지 않는다. 네이티브 Animal 호스트·컨트롤러 자체 비용은 남는다.

미확인: 엔진 내부 본 의존성, compiled ODOL의 실제 피격 헐 위치,14클립의 실제 full-transform/루트/피격 일치, 사망 전환,8→64 비용 및 시각 품질. MLOD 바이트 보존과 네이티브 포맷 검사는 이를 대체하지 못한다.

## 5. 검증 수준

정적 진단·입력 보존·네이티브 형식/메타 검사·빌드·서명 검증 성공. 런타임 회귀·반복 비용 검증·최종 수용은 미실행이다. Workbench 정상 종료는 실패했다. 변환 완료 후 닫을 때 기존 Script is leaking/enf_scriptmodule.cpp:599 assertion을 관찰했고 중단 버튼으로 이번 프로세스만 정리했다. 편집기 문제 해결로 범위를 확장하지 않았다.

## 6. 변경 사항

격리 nf_receiver_subset 데이터 PBO만 새로 생성했다. 기존 PBO·14원본 클립·게임플레이 스크립트·클럭·평가 주기·충돌 검사·DamageSystem 설정은 바꾸지 않았다. 후보는 수신기의 모델·enfanimsys 자산 참조를 바꾸는 격리 데이터 패치이며 현재 운영에는 적용하지 않았다. 원본 모델/골격을 명시한 참조 클래스는 다음 비교용이며 자동 생성하지 않는다.

빌드 SHA-256: `E782FFB56AF6BD3C5673C877CC68AFABCF58FE28F7FFB5439D3373C1F29B8C73`. 기존 핵심 PBO 해시도 재확인했다. 현재 후보는 배포 수용본이 아니다.

## 7. 원시 증거

실행 묶음 receiver-skeleton-review1 / receiver-skeleton-stage1 / receiver-skeleton-compile1. inventory.json, stage.json, compile-audit.json, package-staging.json, packed-proof.json, build/sign/signature 로그와 입력·출력 해시를 보존했다. Workbench UI에서 NF_RECEIVER_SUBSET_DONE accepted=15를 관찰했고 실제 파일15개를 독립 확인했다. source MLOD와 packed ODOL 표현 차이는 기록했다. 원시자료·과거 보고서는 덮어쓰지 않았다.

## 8. 잔여 문제와 다음 작업

다음 단일 관문은 기존 14클립 비교 하네스에 전체 골격 참조 수신기와 축소 수신기를 연결해 실제 본 변환·루트·피격 헐 일치를 일괄 확인하는 것이다. 전체 Health100/6개 피해구역·spine2 기본피격점도 설정/런타임으로 확인한다. 먼저1쌍으로 바인딩을 검증하고 통과할 때만8개체 피격·사망 포함 회귀, 이어64개체 반복 비용 비교로 진행한다. 차이가 나오면 후보 자산을 수정/기각하며 지지·충돌/복구 기능 개발로 확대하지 않는다. 전체 기능·애니메이션 시각·20ms p95는 미수용이다.
