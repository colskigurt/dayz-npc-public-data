# 64→248 고정 쌍 — 서버 포즈 일치, 클라이언트 관측·퇴역 미완료

## 1. 작업 목표
현재64본/full-native 참조와 동일 형상248골격 후보의 공통 CPU 포즈 및 실제 표시를 고정 네트워크 쌍에서 비교한다. 호스트 통합 가능성을 위한 진단이며 기존 물리 최적화나 기능 변경은 아니다.

## 2. 실제 수행
기존 관측기·고정 카메라·Steam 실행기를 재사용하고64본 목록과 현재 참조 타입으로 바꿨다. 관측 addon 서명 검증 및 entity0 서버 컴파일 관문을 통과했다. 서버가 두 개체와 공통64본을 해석했고 클라이언트에서 두 부분 상체 메시를 관찰했다. 그러나 client-ready 신호가 나오지 않았다. 준비 성공으로 간주하지 않고 서버 시작 신호만 별도로 기록하여 포즈를 수집했다. 종료 신호 뒤 서버 퇴역이 확인되지 않아 동일 프로세스 핸들을360초까지 추적하고 종료되지 않은 소유 서버만 정리했다. 클라이언트는 정상 CloseMainWindow로 종료했다.

## 3. 측정 결과
서버 포즈60,736행/64본,18.9483초. 모든 행이 nativeSeconds·updateCount 일치 조건을 만족했고 모델 공간 위치 최대 오차0m였다. 관측 간격은 실제 약50행묶음/초로, 의도했던10Hz 제한과 다르므로 독립 표본60,736회로 해석하지 않는다. 클라이언트 준비·포즈 로그0. 두 CUA 시점에서 두 부분 메시 및 다른 포즈가 표시됨을 확인했으나 프레임별 시각 동등성·부드러움 계측은 없다. 정상 퇴역 마커 없음, 서버 최종 forced=true/실제exit−1.8/64 기능·CPU/Present p50/p95/p99 미측정.

## 4. 원인 분석
확인: 골격 목록64→248 변경은 이 고정 쌍에서 공통64본 서버 포즈를 바꾸지 않았다. 실제 클라이언트에 두 부분 메시가 표시된다. CPU 포즈 일치를 GPU 결과 일치나 전체 본 통합 성공으로 확대하지 않는다.
미확인: 클라이언트 관측기의 준비 실패,10Hz 제한 미작동, 종료 신호·시간 제한에 대한 퇴역 미확인의 정확한 원인. 관측/종료 하네스 문제와 후보의 런타임 문제는 분리되지 않았다. 현재 결과를 후보 채택이나 시각 통과로 처리하지 않는다.

## 5. 검증 수준
컴파일·서명 검증 통과. 서버 포즈 진단 부분 성공. 클라이언트 정량 비교 미실행/하네스 준비 실패, 네트워크 안전 퇴역 미통과. 반복 검증·기능 회귀·최종 수용 없음.20ms p95는 목표로 유지한다.

## 6. 변경 사항
격리 runtime1의 관측 addon·미션·런처 사본만 추가했다. 기존 이동·지지·충돌·애니메이션 시계·배포PBO는 불변이며 입력 해시 후검사 일치. 관측 addon 서명 검증 성공, 개인키 미포함. 생성 단독 시험의 안전 퇴역 성공과 이번 쌍의 퇴역 미확인은 구분한다.

## 7. 원시 증거
ANIM-cardinality64-compile1/network1. runtime-contract1.json, observer build/서명 영수증, plan/launch/terminal/client-closed, script log, cardinality-server-pose.tsv, server-analysis1.json 보존. CUA 화면은 도구 대화의 두 시점 관찰이며 별도 영상/픽셀 동등 증거는 없다. 종료 오류를 정상 종료로 소급하지 않는다.

## 8. 잔여 문제
다음은 게임플레이 기능 확대가 아니라 기존 하네스의 준비·샘플 제한·종료 관문 확인이다. 추가 실행 전 최소한의 진입/resolve/종료 단계 로그로 어디서 흐름이 끊겼는지 확인할 수 있도록 기존 관측기에 국소 계측만 검토한다. 이 관문이 해결되기 전14클립/전체 통합/8→64 성능 확대는 하지 않는다. 물리 비용 절감이나 시각 품질 개선을 이번 결과로 보고하지 않는다.
