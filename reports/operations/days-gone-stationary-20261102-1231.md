## 1. 작업 목표

사용자가 노클립을 끄고 지붕 위에 배치한 Days Gone의 실제 호드 장면에서 CPU·GPU·프레임 표시 계측을 확보하고, 기존 DayZ 바닐라/커스텀 결과와 어디까지 비교할 수 있는지 구분한다. 캐릭터를 여러 장소로 옮기는 조작 시험이나 새로운 최적화 적용은 하지 않는다.

## 2. 실제 수행

사용자 배치 후 컴퓨터 유즈로 지붕 위·호드 가시·HUD 남은 적20명을 확인했다. 기존 exact-build 제어 도구는 무적·탄약·스태미나·챌린지 경과시간 hold를 유지했다. 노클립은 OFF, 충돌 ON, 일반 이동 모드였으며 측정 중 노클립 위치 쓰기나 플레이어 이동은 없었다. 챌린지 타이머 hold는 게임 전체 시간 배율 변경이 아니다.

PresentMon2.6을 대상 프로세스에 한정해75초 실행했다. 사용자 입력 추적은 끄고 기존 최소 WPR 프로파일로 CPU sample/stack만 약8초 수집했다. 파일·네트워크·heap provider를 추가하지 않았으며 서비스·권한 그룹·보안 설정을 변경하지 않았다. CPU 수집·병합이 끝난 뒤30~50초,50~70초의 두 조용한 창을 분석했다. 두 창은 같은 실행의 연속 관찰이다. 별도 반복 실행2회가 아니다.

외부 읽기 전용 관측기는0.25초 간격으로 대상 프로세스 CPU 누적시간, foreground, 플레이어 위치, 군집 상태 분포와 가까운4개 세션 표본을 읽었다. 새 경로 함수 hook이나 뼈대별 조회는 추가하지 않았다. 측정 중 화면 캡처를 반복하지 않고 전후 정지 화면만 확인했다. 화면의 시간적 애니메이션 품질을 검증한 영상은 없다.

측정 전체는74.933초/3746 Present 행이다. 조용한 두 창의 foreground는100%, 플레이어 위치 최대 변화0, 살아 있는 상태 수20~20, 군집 등록 레코드 수300이었다. 상태9의280개 레코드는 이전 검증된 enum상 dead다. 시체·죽은 개체의 물리/렌더/culling 비용을 분리 측정하지 않았으므로20개 살아 있는 감염자만의 순수 씬 비용이라고 부르지 않는다. 별도의 CPU 표본 수집 종료/병합 완료는약26.7초로 두 분석 창보다 앞이었다.

CPU 표본은1ms 간격, 분석 창8.180초, 대상 가중치9756개다. 스택 결합9250개(94.81%), 누락506개(5.19%), 첫IP불일치4개는 inclusive 분석에서 제외했다. Lost Events/Buffers는0이다. 이벤트 손실0과 스택 완전성100%는 서로 다른 판정이다. PE unwind 범위로 leaf/inclusive 후보 RVA를 확보했으나 원본 애니메이션·물리 함수명은 이번에 인증하지 않았다.

선정4개 세션 표본은 각각312행이며 위치와 여러 raw 상태가 바뀌었다. 즉 무리가 정지한 장면만 기록한 것은 아니다. 이 표본은 객체 generation 검증이 없고 CPU 위치/상태 변화이며 실제 표시 포즈의 갱신 빈도를 입증하지 않는다.

비교 참고: 앞선 DayZ64 평지4실행의 V1 p95는24.23~24.44ms, 커스텀 C2는65.47~69.56ms였다. 현재 Days Gone p95는22.12~22.28ms다. 엔진·해상도·씬·살아 있는 수·시체 레코드·이동 방식이 달라 이 차이를 개체당 비용이나 최적화 배수로 환산하지 않는다.

## 4. 원인 분석

확인: 이 Days Gone 장면은 살아 있는 적20명이 움직이는 동안 약20ms 중앙 프레임 간격을 유지했고 두 연속 창의 p95는약22ms였다. GPU busy p95는약6ms였고 프로세스 CPU 합계는약1149~1173ms/벽시계초였다. 프로세스 CPU는 여러 스레드 합계라1000ms/초를 넘을 수 있다.

추정 제한: CPU busy p95약22ms를 순수 감염자 계산 또는 애니메이션 비용으로 해석할 수 없다. VSync/드라이버/프레임 경계와 대기 영향이 섞일 수 있어 이 값만으로 CPU 병목을 확정하지 않는다. GPU busy만으로 전체 GPU/render 비용·애니메이션 최적화 기법도 판별하지 않는다.

현재 비교의 핵심 한계: Days Gone은3440×1440·VSync ON·설정 파일상 frame limit0, 지붕 고정 플레이어/근거리20명 및 죽은 레코드280개다. DayZ는1600×900·VSync ON·60제한·평지 이동 플레이어/64개체 조건이다. 설정 파일 값은 관측 시점의 파일 사본이며 실제 렌더 엔진의 모든 런타임 상태를 읽은 것은 아니다. 카메라와 그래픽 설정은 이번 측정에서 바꾸지 않았다. 따라서 조건 통제된 직접 성능 비교는 성립하지 않는다.

DayZ에서 확인한 Ray/Sphere 경로의 hot range와 Days Gone의 새 무심볼 RVA를 이름만으로 대응시키지 않았다. 이번 자료는 원본의 애니메이션 최적화 구현/VAT/공유 포즈/LOD/발 지지 정책을 밝혔다는 증거가 아니다. 낮은 프레임 시간과 매끄러운 개별 표시 포즈도 동일한 성공 기준이 아니다.

## 5. 검증 수준

- 진단 성공: 실제 장면의 대상 전용 프레임 지표, CPU 표본,20명 유지·정지 플레이어·노클립 OFF 및 정상 도구 종료를 확인했다.
- 반복 검증 완료: 미해당. 한 실행에서 두 연속 창만 수집했다.
- 기능 회귀: 미실행. 등반/낙하/전투의 전 과정을 같은 개체로 추적하지 않았다.
- 시각 품질: 실제 개별 애니메이션 표시 cadence·포즈와 CPU 시계 대응은 미측정이다. 전후 정지 화면을 동영상 검증으로 취급하지 않는다.
- 성능 최종 수용: 미완료. 현재 장면 p95도20ms보다 크고 조건이 다른 DayZ의 개선 근거로 사용하지 않는다.

## 6. 변경 사항

기존 Days Gone 제어 소스는 해시 확인 후 재사용했고 게임 실행 파일/자산/설정 파일 및 DayZ 소스/PBO를 변경하지 않았다. 새 PBO가 없어 이번에는 서명·검증 대상이 없다. 앞선 DayZ 진단 PBO의 서명 성공 기록은 그대로 보존한다. 추가물은 격리 capture-worker/monitor/analyze 및 기존 target-only CPU parser의 DaysGone 대상 어댑터, 조건 사본·보고서다.

PresentMon·WPR·외부 관측기는 종료했다. 사용자의 게임과 무적/탄약/노클립 토글 도구는 유지한다. 노클립은 마지막 확인 시OFF다. active 제어 로그를 안전 종료한 원시 실험처럼 해시 고정하지 않으며, 이번 closed capture 폴더의 증거만 무결성 대상으로 삼는다. 분석 결과를 위해 기존 경로·충돌·애니메이션 로직을 수정하지 않았다.

## 8. 잔여 문제

다음 우선순위는 현재 확보한 Days Gone CPU 스택의 상위 함수 후보를 기존 정적 근거와 연결하여 애니메이션·물리·일반 엔진 작업의 경계를 찾는 것이다. label이 확인되지 않으면 unknown으로 유지한다. 스택 누락5.19%를 줄일 도구/심볼/수집 방식은 별도 검토하며 전부 복원했다고 주장하지 않는다. 현재 결과만으로 DayZ 알고리즘을 바꾸지 않는다.

64개체 직접 비교가 필요하면 이후 사용자가 편한 시점에 살아 있는 수를 늘린 별도 장면을 준비하고 해상도·프레임 제한·씬 조건을 기록해야 한다. 같은 숫자라도 다른 엔진/지도/자산이므로 진정한 matched workload가 된다고 보장할 수 없다. 원본 내부 소유자 연결이 먼저 확인되면 사용자 조작 없이 현재 지붕 환경에서 표본만 추가할 수 있다.

애니메이션 끊김 진단은 기존 DayZ 단일개체 시계/CPU 포즈/표시 시간 연구를 유지한다. 이번 결과는 그 연구를 대체하거나 개선 성공으로 만드는 자료가 아니다. 사용자는 현재 장면을 더 유지할 필요 없이 자유롭게 조작해도 된다.
