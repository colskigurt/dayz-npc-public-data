# 64개체 비용 수집 실패 보존

## 1. 작업 목표

표시용 추가 파트 solid 후보의 기존 평지64개체 CPU·Present 비교를 수행한다.

## 2. 실제 수행

전투 OFF·64논리개체/320표시호스트, 같은12PBO를 고정했다. 기존 관리자 수집기로 대조군15초를 수집했다. 후보는 실행하지 않았다. 수집기 오류 후 같은 PresentMon 프로세스의 실제 종료와 파일을 확인하고, 기존 stop flag로 장면을 안전하게 은퇴시켰다.

## 3. 측정 결과

서버 CPU16표본, 수집 시작 지연177.546ms, 약14.999벽시계초/14.9912게임초,819.2306CPU ms/게임초. 이는 프로세스 전체 관측이며 self-time이 아니다. PresentMon 종료0, stdout Started/Stopped recording, stderr 공백이지만 present.csv 없음. p50/p95/p99 산출 불가. 비용 비교 무효·후보 미실행. 64개체 전체 기능/화면 품질/최종 수용을 판정하지 않는다.

## 4. 원인 분석

확인: 대상 클라이언트와 서버가 살아 있었고 클라이언트 관측기는 활성true/320파트를 기록했지만 ETW CSV가 없었다. 수집 후 화면에는 다른 창이 게임 일부를 가렸다. 미확인: 수집 중 실제 가림 상태와 렌더링 여부, ETW 이벤트 미수신 원인. 이후 화면 관측을 과거 전체 구간의 상태나 원인으로 소급하지 않는다. 종료0을 수집 성공으로 간주하지 않는다.

## 5. 검증 수준

미션 컴파일/장면준비/서버CPU 관측: 성공. Present 수집: 실패. OFF/ON 성능 비교·기능 회귀·시각 품질·20ms 목표: 미검증. 서버 RequestExit0 이후 exit -1, 클라이언트 정상 닫기 확인.

## 6. 변경 사항

격리 시험 미션에서 추가 파트 solid 속성 후보와1Hz 대칭 상태 관측기를 준비했다. 실제 실행은 OFF만 수행했다. 기존 PBO/서명/게임코드 변경 없음. 기존 실패 파일과 원시자료를 덮어쓰지 않았다.

## 7. 원시 증거

실행 ANIM-host-solid-flat64-1-off. closed.json, stdout/stderr, server-process-cpu.csv/json, 서버 종료/클라이언트 닫기 기록, 고정 시험 계약. 공개 자료에는 경로·PID·원시 개인정보를 제외한다.

## 8. 잔여 문제

다음 비교 전 실제 게임 창을 Computer Use로 선택·확인하고, CSV 생성과 수집 전체 구간을 검증해야 한다. 현재 실패를 후보 성능 결과로 사용하거나 유리한 결과가 나올 때까지 반복하지 않는다. 실패 원인을 확정하지 못했으므로 첫 재시도도 별도 실행ID로 보존하고, 다시 같은 수집 실패면 ETW 수집 문제를 먼저 분리한다.
