## 1. 작업 목표
지속 등반과 정상 밀침을 보존하면서 접근 감속이 현재 커스텀 NPC의 실제 충돌 계산을 줄일 근거가 있는지 판단한다. 기존 연구를 먼저 확인하고 신규 구현·게임 실행은 하지 않는다.

## 2. 실제 수행
기존 rear-pressure 분류와 route-progress 분석을 재사용해 방금 종료한 OFF 기준 실행을 읽기 전용으로 재분석했다. 입력 경로/실행 ID와 미회수 종료코드의 관찰 영수증 처리만 바꾸고 분류 임계값·수학은 유지했다. 기존 자료의 재분석이며 새 독립 게임 반복이나 성능 비교가 아니다.
별도 NorthFrontierHorde의 native infected 이동과 현재 AnimalBase 커스텀 실행기를 구분했다. Mi/RVO 인계문의 제어 아이디어를 그대로 복사하지 않았다. 현재 소스의 native root delta 소비·접촉 소비·DriveGround 및 압력 적분 호출 관계를 확인했다.

이번 안정 경로/동일 세대 지상 보행 표본은1,161.371개체초였다. 그중 경로방향 진행률0.05m/s 미만100.252개체초(약8.63%), 이후 Displace2,002회 중1,997회 수용됐다. 해당 표본의 평균 실제 이동은0.179m/s, 경로 진행은−0.104m/s였다. 즉 제자리처럼 보이는 동안에도 실제 접촉 이동이 있었으며, 대부분이 단순 실패 반복은 아니었다. 이 집계와 rear 분류는 정의가 달라 서로 교집합이나 독립 구간으로 더하지 않는다.
표본 수·호출 비율은 제거 가능한 CPU 상한 또는 감속 절감률이 아니다. Present p50/p95/p99·감속 후보 비용·화면 품질은 미측정이다. 이번 OFF 실행 자체의 클라이언트 cadence 불일치 경고는 그대로 유지하며 다른 실행과 CPU 인과 비교에 사용하지 않는다.

## 4. 원인 분석
확인한 호출 관계:
- DGBNativeGround.DriveGround는 MoveTo 뒤 SolveContacts를 호출한다. 이동량을 줄였다고 이 경로가 자동 생략되지는 않는다.
- DGBGroundAgent.MoveTo의 UseNativeRootDelta 분기는 speed×dt로 만든 step을 native delta로 다시 대체한다(193~245행 부근). 따라서 속도 float만 낮추는 제안은 실제 이동 제어점이라는 보장이 없다.
- Drive는 native 이동 뒤 ConsumeContact를 호출한다. ContactVelocity는 별도 질량·스프링·감쇠로 적분되므로 보행 의도만 낮춰도 기존 압력 제안이 즉시 사라지지 않는다.
- Crowd.Update는 PressureProposal/ContactForce를 매번 초기화한다. 표본의 0을 보고 그 사이 압력이 없었다고 해석할 수 없다.
추정: 후열의 전진 압력을 낮추면 장기 밀집과 압력 소비가 감소할 수 있다. 반대로 해소 유량이 떨어져 밀집 체류가 길어질 수 있다. 현재 자료로 어느 쪽인지 판정할 수 없다.
결론: 단순 감속을 CPU 최적화로 바로 구현할 근거가 부족하다. 명목 입구 제외 후 남는 호출 비율은 두 자료 모두 작고, 실제 fitted entry 보호를 아직 증명하지 못했다. 기존 rear-stop 우선순위 하향 결정을 유지한다.

## 5. 검증 수준
소스 연결 및 읽기 전용 분석: 진단 성공. 감속 구현·컴파일·8/64 기능 회귀·반복 성능·시각 품질·최종 수용: 미실행. 기존 분류기를 다른 보존 실행에 적용한 것이지 새로운 독립 통제 실험이 아니다.

## 6. 변경 사항
기존 실험 폴더 안에 읽기 전용 분석 스크립트와 결과·조건표만 추가했다. 게임 소스·PBO·설정·원시 기록 변경 없음. 신규 배포 PBO/서명 대상 없음. 현재 소스 해시와 기존 분석 입력 해시를 저장했다. 이 소스 검토만으로 실행 바이너리 전체 일치를 증명했다고 주장하지 않는다.

## 7. 원시 증거

## 8. 잔여 문제
접근 감속의 적용 조건은 다음과 같이 고정한다.

| 구분 | 적용 전 요구 근거 / 금지 조건 |
|---|---|
| 관측 | 유효 경로 접선·동일 경로세대·실측 전진속도와 외부 접촉 이동을 구분. 감속 명령 자체로 낮춘 속도를 혼잡 근거로 재사용하지 않음 |
| 보호 | 활성 등반·진입 정렬·실제 출구 footprint·피격·사망·낙하·착지·복구·회피 소유권이 있으면 감속 금지 |
| 제어점 | 실제 native root/명령 소비 경로를 검증. speed float 변경이 곧 실속도 변경이라는 가정 금지. 애니메이션 시계 둔화 금지 |
| 비용 | 추가 이웃검사·EMA·상태 전환 비용을 포함해 전체CPU와 Displace/실제 물리 질의·유량을 함께 비교 |
| 탈출 | 해소 시 복귀·목표변경 무효화·최대지연·최소전진 보장 필요. 시도 자체를 무기한 대기시키지 않음 |

이 조건을 갖추기 위해 또 기능 개발을 확대하기보다 현재 감속 구현은 보류한다. 다음 높은 가치의 의사결정은 기존 FOLLOW 비용 중, 감속 없이 실제 질의 호출/호스트 수를 줄일 수 있고 과거 기각 사유가 해소된 후보가 남는지 판정하는 것이다. 이미 실패한 SupportSweepFast/Scratch/4파트/LOD/복합 Drive-Displace를 동일 조건으로 재실행하지 않는다. 검증된 국소 후보가 없으면 엔진 접근 한계를 명시하고 근거리64 최적화와 원거리 Simulation LOD를 분리해 사용자에게 제시한다.
