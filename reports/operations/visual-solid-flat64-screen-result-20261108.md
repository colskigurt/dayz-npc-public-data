# 표시 호스트 solid64 비용 선별 미통과

## 1. 작업 목표

추가 표시 호스트의 solid만 false로 바꾼 후보가64개체 전체 CPU 및 Present 비용을 줄이는지 사전 기준으로 선별한다. 기존8개체 OFF/ON 단일 기능 통과와 별개로 판정한다.

## 2. 실제 수행

전용 시간에 같은12PBO·동일 미션·평지/카메라/플레이어 입력·1280×800/VSync0 조건의 OFF→ON 한 쌍, 각15초를 수집했다. 게임 창은 Computer Use로 수집 전 확인했고 수집 중 화면 캡처/입력은 하지 않았다. 전체 구간의 클라이언트 활성·64개체 생존/인식/2m이상 이동·320파트 콜백 범위를 기존 분석기로 검증했다. 이전 CSV 실패 및 사용자 취소/준비 만료 실행은 새 반복으로 합치지 않았다.

## 4. 원인 분석

확인: 서버 CPU는 소폭 낮고 클라이언트 프레임 지표는 높아 전체 성능 개선 기준을 만족하지 못했다. 논리 지지/월드 검사량은 거의 같은 범위다. 추정: 추가 호스트 solid만 조정하는 방식으로 주력 Ray/Sphere 비용을 제거하기 어렵다. 미확인: 서버 변화의 인과성, 클라이언트 악화 원인, 실제 native contact 처리량, 클라이언트 solid 복제, 네트워크 및 스케줄링 영향. 단일 쌍으로 후보가 항상 느리다고 확정하지 않는다. 이 장면p95가20ms 미만이어도 전투/고지대 밀집을 포함한 전역 목표 달성은 아니다.

## 5. 검증 수준

64평지 수집·전체 구간 검증: 진단 성공, 단일 비교 완료. 최적화 선별: 실패/미수용. 이전8개체 이동 기능은 별도 단일 비교 통과. 이번64평지 시험은 고지대/전투/피격/사망 회귀나 시각 부드러움 최종 수용이 아니다. 양쪽 서버 RequestExit0후 실제exit−1이며 정상 서버 종료 통과로 보고하지 않는다. 클라이언트 정상 닫기와 수집기 종료 확인.

## 6. 변경 사항

격리 미션/flag만 사용했다. 같은 관측기를 양쪽에 적용했고 바디 속성 검사는1Hz였다. 원래 레이어·대표 물리·논리 지지/접촉/낙하·착지·애니메이션 시계는 유지했다. 기존 PBO/배포 코드/자산/서명은 변경하지 않았다. 새 서명 대상 없음. 후보를 기존 기본 실행에 반영하지 않는다.

## 7. 원시 증거

ANIM-host-solid-flat64-dedicated-1-off 및2-on. 원시 Present CSV, 서버 CPU CSV/JSON, 전체 상태 TSV, 파트 시계·solid readback, 기존 분석기 결과, 종료 기록, 사전 계약을 SHA256으로 연결했다. 공개 JSON은 집계/해시만 제공하며 로컬 경로·PID·개인정보를 제외한다.

## 8. 잔여 문제

이 후보의 수용 시험은 여기서 종료하고 결과·실패를 보존한다. 다음 단일 산출물은 기존 SupportSweepFast/Scratch/지지 문맥 연구의 실패·비용 근거와 이번 약2.56만ray/게임초를 대조한 물리 질의 작업량 절감 후보 선정이다. 추가 호스트 물리 제거/레이어 변경의 반복, 무조건 캐시/지지 강제 성공, 기능 복구 작업으로 범위 확대는 하지 않는다. 새로운 후보는 구현 전에 근거·위험·최소 검증 조건을 먼저 제시한다.
