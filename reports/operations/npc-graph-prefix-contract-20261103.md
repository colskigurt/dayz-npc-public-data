## 1. 작업 목표

부모 필드의 송수신 위치 차이보다 앞선 구간을 확인한다. 그래프 데이터 직렬화가 끝날 때 이미 어긋나는지, 공통 위치·회전 header 내부에서만 어긋나는지 구분해 수정 범위를 좁힌다.

## 2. 실제 수행

기존 1개체·8파트 격리 시험의 완료 결과를 회수했다. 서버 emitter 문맥에서 그래프 encoder 4e9290 호출 전후와 header 진입 위치를, 클라이언트 dispatcher 문맥에서 decoder 4e68a0 호출 전후와 공통 reader 진입 위치를 읽었다. 관측기는 클라이언트 재개 전에 연결했다. 게임 필드 쓰기 없이 기존 byte guard를 유지했다. 훅을 사용했으므로 성능 시험으로 취급하지 않는다.

동일 실행의 유효 레코드 전체 내용과 각 위치를 대조했다. 서버·클라이언트 관측 오류0, 서버 cleanup error 없음, 클라이언트 메시지 truncation 없음과 REA 종료를 확인했다. 소유 게임 프로세스는 이미 종료됐으며 재실행하지 않았다. 별도 공유 dispatcher/header 분석은 완료된3함수를 재사용했다. 새 후속 정적 분석은 아직 해석하지 못한 그래프 encoder/decoder 두 함수만 대상으로 실행 중이며 완료 증거에 포함하지 않았다.

16바이트 레코드8건씩에서 위 값이 모두 같았고 유효 내용은8/8 일치했다. 시작 위치는 같지만 그래프 codec을 나온 시점에 이미15비트 차이가 있다. 그 뒤 부모 필드까지 소비량은 서버83비트·클라이언트19비트다. 따라서 전체79비트 차이가 그대로 단일 그래프 필드 길이라고 해석해서는 안 된다. 앞선 분기 해석 차이로 하류 소비량도 달라졌을 가능성을 조사한다.

기존 128비트 선언 범위에서 부모 읽기 종료146비트·18비트 초과도 이번 실행에서 재현됐다. 비정상 ID 자체의 끝은 bit113으로 선언 범위 안이다. 범위 초과가 ID 생성의 선행 원인이라는 설명은 맞지 않는다. 클라이언트 초기111바이트 입력8건의 graphRead=null은 이번 선택 훅의 관측 범위 밖이라는 뜻이며 그래프 데이터가0이라는 뜻이 아니다.

새8/64 기능 회귀, 실제 시각 품질, Present/CPU/GPU p50/p95/p99, 할당·GC는 측정하지 않았다. 20ms p95는 목표다. 동일 원시 자료의 재분석을 새 독립 반복으로 세지 않는다.

## 4. 원인 분석

확인: 부모 setter에 도달하기 전, 그래프 데이터의 송수신 소비량부터 다르다. 따라서 부모 ID만 강제로0으로 만들거나 부모 경고를 숨기는 방법은 선행 계약 불일치를 고치지 않는다. 전송 중 내용 변조는 이번 동일 바이트 표본에서 관찰되지 않았다. 모든 전송의 무결성이나 엔진 전체 결함을 증명한 것은 아니다.

가설: 그래프 변수 구성·초기화 또는 command/네트워크 역할에 따른 조건 차이가 그래프 serializer의 필드 소비에 영향을 줄 수 있다. 서버 command bind 로그8건·클라이언트0건은 기존 관측이지만 원인으로 확정하지 않았다. 바인딩 강제 추가나 생성 플래그 변경은 아직 하지 않는다.

기존 설명 정정: c0bc40을 eligibility guard로만 분류했던 설명을 철회한다. 완료된 전체 역컴파일에서는 네 바이트의 비트 직렬화와 graph encoder 호출도 확인됐다. 상위 의사코드의 추론된 시그니처가 살아 있는 stream 인자를 생략했으므로, 그 의사코드만 보고 검사 함수라고 판단한 범위를 정정한다. 과거 보고서는 보존한다.

미확인: 그래프 내부 최초 불일치 명령, 공식 mod API로 수정 가능한 지점, 이 오류의 CPU 비용과 화면 영향은 미확정이다. 이전 오프라인 비용 실행에는 이 네트워크 경고가 없었으므로 과거 커스텀65~70ms p95 전체 원인으로 확대하지 않는다. 애니메이션 시계의 기존 mode0 시간 손실과도 별개로 관리한다.

## 5. 검증 수준
