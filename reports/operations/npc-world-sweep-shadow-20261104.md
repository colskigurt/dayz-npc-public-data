# CPU 비용 최적화 복귀와 관절 Sweep 예비 진단

## 1. 작업 목표

64개체 CPU·물리 비용 최적화를 주력으로 복원한다. 기능 개발과 게임 연결 연구는 보류·보존한다.

## 2. 실제 수행

DriveGround→ConsumeContact→Displace의 입력과 상태 확정 순서를 기존 코드로 확인했다. Displace는 새 위치·minimumLift·접촉 결과를 사용하고 실패/낙하 처리가 달라 단순 병합 또는 결과 재사용을 배제했다. 별도 shadow 시험에서 네 관절 Sweep의 전체 영역을 포함하는 BoxOverlap을 추가하되 기존 지지 Ray 및 모든 Sweep은 그대로 실행했다.

## 3. 측정 결과

격리 서버 1회, 128입력. 빈 영역 29, 실제 관절 충돌 합계 30, false-clear 0, 기존/진단 결과 계약 일치 128/128, 포즈·루트 불변 128/128. 생략된 검사 0. p50/p95/p99·64개체 비용·시각 품질은 미측정이다. 기존 8 PBO 서명 검증 성공, 새 PBO 없음. 완료 표식 후 소유 서버를 종료했으며 정상 종료 인증은 아니다.

## 4. 원인 분석

확인: Drive와 Displace는 서로 다른 이동 요청이므로 연속 호출만으로 중복이라 할 수 없다. 후보 원리: 큰 영역이 비었을 때 포함된 네 관절 Sweep을 생략할 가능성. 미확인: Overlap 추가 비용 대비 절감, 동적 환경과 모든 형상의 포괄성. 시험 생성기의 나눗셈이 정수 구간이 아닌 소수 previousMode/heading을 생성했다. 실제 TSV는 유효 관측이지만 의도한 조합 커버리지 증거로 수용하지 않는다.

## 5. 검증 수준

예비 진단 완료·정식 수용 보류. 기능 회귀 미실행, 반복 검증 미실행, 성능 개선 미입증. 기존 terrain 대체 계열은 비용 gate 실패로 보류하며 추가 미세변형을 자동 반복하지 않는다.

## 6. 변경 사항

world-sweep-shadow1의 격리 mission/runner만 추가. 게임 소스·배포 PBO·운영 서버 불변. 엔진 SHA256 4bbf370b1d479e0556e916d21213bafba383cbdd3a12c6e2518cd49c1ca64e70. 기존 1.29 주소나 비용과 직접 합산하지 않는다.

## 7. 원시 증거

실행 ID world-sweep-shadow1. 같은 폴더의 plan.json, init.c, server-launch-BProbe.json, server-profile-BProbe/world-sweep-shadow.tsv, analysis.json. 고정 평지·지붕·경계·벽 옆 입력이며 실제 64명 추격 시험이 아니다. 원시 자료 해시는 아래 무결성 목록에 있다.

## 8. 잔여 문제

다음 단일 산출물은 정확한 입력 조합과 기존 판정 보존을 전제로 한 관절 Sweep broadphase의 채택/기각 비교표다. 먼저 생성기 구간을 명시 정수화하고 양성/음성 대조를 확인해야 한다. 그 뒤 기존 검사와 후보의 국소 비용만 비교한다. 유망하지 않으면 기각하며 기능 복구·장시간 64회귀로 확대하지 않는다. 20ms p95는 여전히 목표다.
