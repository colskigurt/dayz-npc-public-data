# 후보 검증·채택 기준 — 2026-11-03

상태: 향후 비교의 사전 기준. 이번 문서 작성으로 시험을 실행한 것이 아니다. 기존 실행을 새 기준의 통과로 소급 분류하지 않는다.

## 단계와 중단 조건

1. 정적/국소 계약: 후보의 실제 사용·원본 위임·음성 대조·원래 안전 판정 보존을 확인한다. API 의미가 다르거나 거짓 안전 판정이면 중단한다.
2. 국소 비용: 현재 지형 후보는 같은 입력/포즈/할당 수명/관절 Sweep 꼬리를 사용한다. REF/ON 순서와 역순의 2독립 프로세스에서 전체 메서드 중앙값 각각5% 이상 감소, 비적격 경로 증가는 각각3% 이내를 요구한다. 이 미달이면 군집 시험으로 확대하지 않는다. ticks는 경과 카운터이며 CPU self-time이 아니다.
3. 유망 후보의 최종 기능 비교: 고정8개체·64개체 시나리오에서 기준/후보 각각 사전 지정3회(동일 seed/replay별 짝) 비교한다. 유효한 동일 기준 빌드 결과가 있으면 재사용하되 조건 해시가 다르면 재사용하지 않는다. 반복 순서와 실행 수를 시작 전에 고정한다. 성공할 때까지 반복해서 좋은3회만 고르지 않는다. 크래시·잘못된 상태 전이·거짓 지지 시 조기 중단하며 미실행 잔여 수를 기록한다.
4. 전체 비용 비교: 클라이언트 Present/CPU Busy p50/p95/p99와 서버 CPU 작업량/게임초·벽시계초, 게임시간/실시간 비율, 실제 처리량을 구분해 같은 관측 구간에서 비교한다. 서버 dt p95·미션 callback dt·Present p95를 합치거나 서로 대체하지 않는다. CPU 작업량과 Present p95는3짝 모두 개선 방향, 짝별 상대 변화의 중앙값 각각5% 이상 감소를 후보 성능 진전 기준으로 정한다. 이는20ms p95 최종 목표 달성과 별개다. 3짝으로 통계적 확실성이나 일반적인 모든 맵 성능을 주장하지 않는다.
5. 시각 품질: 고정 카메라/거리/동작·시간축 조건의 실제 화면으로 별도 판정한다. CPU 본 변화·평균1배 속도·녹화fps만으로 통과시키지 않는다. 화면 검증이 없으면 미검증으로 남긴다.

## 기능 계약과 기준 빌드 결함

- 고정 시나리오의 완료 조건은 개체별로 판정한다. 최종 수용에는8/8·64/64의 유효 종료와 요구된 저지대/고지대/하강/재등반 이력, 미해결 혼잡·등반 종료 계약 위반0을 요구한다. 같은 좁은 지붕에 전원이 동시에 남을 필요는 없다.
- 정상 밀침→낙하→착지→FOLLOW/재등반은 허용한다. 정상 낙하를 실패율로 합산하지 않는다. 이력 미충족·현재 FOLLOW·현재 정체·종료 직전 시작된 전환을 구분한다.
- 후보에서 실패가 나오면 동일 기준 빌드/입력에서 재현 여부부터 확인한다. 기준에도 있는 결함은 별도 ID로 보존하며 해당 최적화의 새 회귀로 단정하지 않는다. 기존 기능 통과율이나 예산을 낮춰 수용하지도 않는다.
- 기준 결함이 있어도 격리 비용 비교는 진행할 수 있다. 기능 최종 수용은 미완료로 유지하며, 최적화 작업 전체를 기능 복구로 전환하지 않는다.
- 정체 하나를 수정할 때마다 전체3회 세트를 다시 돌리지 않는다. 변경된 계약의 최소 검증 후 최종 후보에서 고정 세트를 사용한다.

## 비교 동결 항목

기준/후보 build·모듈/PBO hash, 미션·fixture·이동 replay·seed·시간 제한, 개체 수/호스트 수, 전투/밀침/지지 옵션, 카메라/해상도/VSync/FPS 제한, warmup/관측 구간, 계측 도구와 활성 여부를 기록한다. 결과를 본 뒤 도착 기한·도달 정의·허용 오차를 넓히지 않는다. 필요한 변경은 별도 버전으로 만들고 기존 실패를 남긴다.

## 현재 우선순위

현재 단일 후보는 비지형 Overlap 인증+지형 높이/법선 조회의 국소 비용 비교다. 단일 API 진단만 통과했다. 골반/접근/입구방향 후보는 보존·후순위다. 근거리 K명 정밀 처리와 원거리 Simulation LOD는 별도 미래 연구이며, VAT는 DayZ에서 지원되는 실행 경로가 확보되지 않았다. 이번 검토로 구현에 착수하지 않는다.
