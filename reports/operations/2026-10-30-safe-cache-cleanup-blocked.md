# 안전한 캐시 정리 검토 — 삭제 실행 차단

## 1. 작업 목표

캐시와 재빌드 출력 중 안전하게 지울 수 있는 항목만 확인하고 정리한다. 원시 실험과 현재 작업 자료를 보존한다.

## 2. 실제 수행

27개 캐시 폴더와 재빌드 후보 세 곳을 조사했다. Python 캐시는 원본 .py가 존재하는 경우만 선정했다. 빌드 임시본은 현재 Source와 파일 전체의 SHA256이 일치하고 24시간보다 오래된 5개 폴더만 선정했다. Git 추적 여부, 명시적 증거 참조와 경로 범위를 확인했다. 삭제 직전 전체 검증 후 파일 단위로 제거하는 명령은 자동 승인 정책에서 실행 전에 차단됐다. 우회 시도는 하지 않았다.

## 3. 측정 결과

- 삭제 예정: 361개 파일, 4,486,454바이트(약 4.28MiB).
- 소스가 있는 Python 캐시: 3,673,798바이트.
- 현재 소스와 동일한 오래된 빌드 임시본: 812,656바이트.
- 실제 삭제: 0개. 확보 공간: 0바이트.
- 차단 후 대상 361개 파일이 모두 존재하고 해시가 계획과 일치함을 확인했다.
- 소스·서명 키·배포본·기존 체크포인트 등을 포함한 보호 파일 197개의 해시가 검토 전후 일치했다. 원시 실험 기록 디렉터리는 삭제 명령 대상에 넣지 않았다. 원시 기록 전체를 재해시한 것은 아니다.
- 8/64개체 시험, p50/p95/p99 및 애니메이션 화면 검증: 이번 유지보수에서 미실행.

## 4. 원인 분석

확인된 사실: .build는 순수 캐시 폴더가 아니다. 실제 실행 DLL, 시험 씬, 고유 분석 자료와 과거 소스가 혼재한다. PassthroughLab 출력과 기존 모델 binarize 전체의 안전한 재생성은 입증하지 못했으므로 보존했다.

미확인: 모든 원시 증거 의존성, 전체 파일 핸들, 전체 재빌드 재현성. 참조 색인은 완전한 의존성 그래프가 아니다.

차단 원인: 자동 승인 검토가 삭제 명령에 'blocked by policy'를 반환했다. 더 구체적인 사유는 제공되지 않았다. 파일 접근권한 실패나 삭제 실행 중 실패로 해석하지 않는다.

## 5. 검증 수준

정리 대상 식별 및 해시 검증: 진단 성공. 실제 삭제: 미실행·정책 차단. 게임 기능·시각 품질·성능 회귀: 미실행. 최종 정리 완료로 판정하지 않는다.

## 6. 변경 사항

검토 계획과 차단 후 검증 결과만 새로 저장했다. 게임 소스, PBO, 서명, 기존 실험 기록은 변경하지 않았다. 빌드 식별자는 새로 만들지 않았고 서명·빌드 검증을 재실행하지 않았다.

## 7. 원시 증거

로컬 cleanup-review/2026-10-30/cleanup-064946의 plan.json 및 outcome.json. 이전 storage-inventory.json과 reference-protection-index.json을 사용했다. 삭제 계획에는 파일별 크기·SHA256과 보존 소스의 SHA256을 기록했다. 전체 로컬 경로·개인 키·프로세스 정보는 공개 보고서에서 제외한다.

## 8. 잔여 문제

실제 정리는 정책 차단으로 미완료다. 재실행 전 파일 상태를 다시 확인해야 하며 이번 계획을 영구 삭제 규칙으로 삼지 않는다. 큰 용량 절감은 원시 실행 기록의 검증된 외장 보관에서 기대할 수 있지만, 이 작업에서는 복사·압축·이동·삭제하지 않았다. 애니메이션 진단 및 64개체 실험 조건은 바꾸지 않았다.
