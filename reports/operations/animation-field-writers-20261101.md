# 애니메이션 시간 필드 쓰기 조사: Head 타이머와 Entity 초기값 구분

작성: 2026-11-01T14:16:59.521298+09:00

## 1. 작업 목표

앞선 안정 조회 조건에서 확인한 애니메이션 누적 시간 손실에 대해, 기존 공개 API 조사와 중복되지 않는 쓰기 경로를 조사한다. 지원되는 수정 접점을 찾기 전 기존 NPC 실행 구조를 변경하지 않는다.

## 2. 실제 수행

기존 공개 API·정밀도 setter 호출·Update 계약·누적기 스케줄러 기록을 먼저 대조했다. 동일 SHA의 설치 실행 파일을 읽기 전용으로 사용해 0x228/22c/250/254/66c 변위 바이트를 찾고, PE unwind 구간 시작부터 Capstone으로 디코드해 메모리 쓰기 피연산자를 분류했다. 이는 REA 런타임 계측이나 완전한 CFG 분석이 아니다. 알려진 REA provider 제약에 대해 설치나 재설정을 반복하지 않았다.

후보에서 Head/Entity 생성자, Head 갱신 함수, 알려진 leaf setter를 좁혀 명령·구간 해시를 보존했다. RTTI와 가상 함수 표를 통해 같은 오프셋의 다른 클래스 필드를 구별했다. 게임 프로세스·클라이언트·영상·PBO를 새로 실행하거나 생성하지 않았다.

## 3. 측정 결과

정적 후보 unwind 구간 913개에서 메모리 쓰기 140개를 분류했다. 이는 감염자의 유효 쓰기 140개라는 뜻이 아니다. 구간 끝까지 디코드되지 않은 후보 35개와 unwind에 연결되지 않은 바이트 적중 75개가 남는다. 직접 leaf setter 두 개는 알려진 진입점에서 별도 제한 디코드로 보존했다.

0x140a289c0의 RTTI는 Head이며, Head 가상 함수 표의 +0x880은 0x140a29830을 가리킨다. 이 함수의 +0x66c 감소·재설정은 감염자 누적기와 같은 오프셋이라는 이유만으로 같은 기능으로 볼 수 없다.

Entity 기본 생성자 0x140a5dda0은 +0x228/22c/250에 float32 약0.06666667초, +0x254에 약0.2초를 초기화한다. 이 값은 앞서 실제 Animal에서 관찰한 0.05초를 대체하는 측정이 아니며, 생성자 뒤 설정·계층의 영향을 구분해야 한다.

이번 p50/p95/p99·8/64 안정성·GPU/표시·시각 품질은 미측정이다. 직전 별도 64개체 기능 통과와 script p95=68ms 결과는 보존하며 이번 성능 결과로 재사용하지 않는다. 20ms p95 목표는 미달성이다.

## 4. 원인 분석

확인된 사실: 변위 일치만으로 시간 필드 소유자를 정하면 Head 타이머를 Animal 애니메이션 누적기로 잘못 연결할 수 있다. 기본 Entity 초기화 값과 현재 Animal의 실제 간격도 다르다. 기존 실측된 0x140b72410의 누적·임계 평가·0 리셋 경로는 유지된다.

추정: 현재 50ms 간격은 기본 생성자 뒤의 계층/정밀도 정책에서 설정될 수 있다. 이번 생성자 분류만으로 실제 적용 호출 순서나 설정 가능성을 확정하지 않는다.

미확인: 스크립트에서 임의 간격·잔여 시간 보존을 제어할 수 있는 지원 인터페이스. 발견하지 못했다는 결과를 불가능하다는 증명으로 보고하지 않는다. 동일 instance duration은 혼합 시간이며 dt 전달 용도로 쓰지 않는다.

## 5. 검증 수준
