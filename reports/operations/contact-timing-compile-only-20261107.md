# 접촉 계측 후보: Enforce 컴파일 통과·실제 솔버 미검증

## 1. 작업 목표
기존 접촉 시간계측 생략 후보의 Enforce 컴파일과8개체 분석기 허위 통과 방지 조건을 확인한다. 성능 측정과 분리한다.

## 2. 실제 수행
클라이언트 없이 현행 서버에서 후보 모듈을 로딩했다. NPC를 생성하지 않고 Mission 최초 갱신에서 즉시 종료 요청했다. 첫 미션은 OnUpdate 인자명dt가 엔진timeslice와 달라 실패했으며 World 모듈은 컴파일됐다. 소유 프로세스 확인 후 강제 종료를 별도 기록하고 원문을 보존했다. 미션 인자명만 수정한 독립 compile2에서 World/Mission/첫갱신을 확인했다. 후보 PBO는 변경하지 않았다.8개체 기존 분석기를 재사용하고 상세 시간Unavailable/실제 질의 카운터 검증을 추가했다.

## 3. 측정 결과
compile2의 명시 성공 marker,오류 없음,완료/종료요청 및 실제 서버 종료를 확인했다. NPC0,클라이언트0,솔버 실행0이다. 분석기 합성 정상조건2개 통과,누락개체/중복/숨은계측/물리호출0/광선삭제/잘못된arm/Unavailable누락/비정상수치 계열의 잘못된 입력7개 거부. 이는 게임플레이나 CPU 개선 결과가 아니다. 새로운 p50/p95/p99·애니메이션·8/64 기능 결과 없음.

## 4. 원인 분석
확인:후보 타입·override가 현행 엔진에서 컴파일되고 미션이 시작된다. 첫 실패는 별도 컴파일 미션의 인자명 오류였다. 미확인:실제 본/접촉 솔버 실행의 OFF/ON 동등성,상태회귀,성능 절감. 시간0/호출없음을 성공으로 오인하는 분석기 입력은 거부한다. 검증기는 source proof를 런타임 증거로 대체하지 않는다.

## 5. 검증 수준
Enforce 컴파일/미션 시작 진단 성공. 분석기 부정조건 검사 성공. 솔버 실행·8명·64명·시각·성능·최종수용 미실행. 서버 실제종료-1로 정상 프로세스 종료 수용은 아니다. 첫실패 외부강제종료는 runner forcedStop=false와 별도 owned-stop 영수증을 함께 해석한다.

## 6. 변경 사항
후보 PBO BBCAC26DD0A80F578C3789D236DFADDF6CC2108C85AE27E58579F0F746F6BC67 유지. 기존 서명 및 검증 성공,새 서명/PBO없음. validate_timing_policy.py,eight1/analyze.py,두 compile fixture와 실행결과/분석만 추가했다. 기본OFF·기존 게임코드 불변.8개체 계획/성능 수용 임계값을 변경하지 않았다.

## 7. 원시 증거
ANIM-contact-timing-compile1/2의원문로그/종료기록/미션/manifest,compile-validation.json,analyzer-gate-selftest.json 및 검증기코드를 보존한다. 로컬 체크포인트에서9개 입력 파일을 검증했고 해시는 공개 JSON에 연결했다. 검증은 실제 저장자료에 대한 것이며 합성 입력검사를 실제게임 반복으로 세지 않는다.

## 8. 잔여 문제
전용 시간 확보 후8개체 양쪽을 실행해 원본 물리카운터·4경유·낙하복귀·수신기 정합성을 검증한다. 그 전에는 비용 개선을 주장하지 않는다.64외부CPU/Present 비교는 다른 게임 부하를 제거한 조건에서만 진행한다. 기존 Fast 미수용/실패 기록과 애니메이션 품질 잔여조건은 유지한다.
