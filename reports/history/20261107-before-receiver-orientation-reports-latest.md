# 현행5파트64 평지 기준비용3회

## 1. 작업 목표

현재5파트64개체 평지 추격의 반복 기준 비용과 실제 ETW 수집기 수정 효과를 확인한다. 새 최적화가 없는 baseline 반복이다. 정상 밀침·낙하·착지·FOLLOW·재등반 코드와 기존 기능 자료를 보존한다.

## 2. 실제 수행

기존 flat-cost2의5파트 조건,같은12개 PBO·미션·카메라/NFVanillaMetrics 입력·1280×800·VSync0·FPS상한500을 재사용했다. 64논리개체·320표시파트,비전투 평지에서 새 서버/Steam클라이언트/프로필을3회 실행하고 각각15초 ETW를 수집했다.30초 준비·64개체 인식/2m이동·전체20m내·카메라/클라이언트와 서버의 실제플레이어 이동·전경 조건을 만족한 뒤 요청했다. 보수적 전경/서버 문맥 범위 전체를 검증하고 일부 유리한 구간만 잘라내지 않았다.

초기 관리자 도우미가 준비 전 종료되어 조사했다. 앞선 수정 파일을 UTF-8 BOM 없이 저장한 탓에 실제 호스트 Windows PowerShell5.1이 한글을 잘못 해석하는 구문 오류를 재현했다. BOM 저장·JSON 명시UTF8 읽기로 수정하고 같은PS5.1에서 사전검증 및0/7/CSV없음3조건을 재검증했다. 이후 실제 관리자도우미가 준비됐고3회 모두수집했다. 이는 최초PS7검증의 범위 부족을 보완한 것이다.

초기 준비 스크립트는 다른HIGH씬의 날씨 마커를 요구하여 gate 전 거부됐다. 평지 원본에는 해당마커가 없으므로 그 요구만 분리한 어댑터를 사용했다. 이후 실제이동준비 미충족을 대기 가능한 상태로 취급했으며 이동조건 자체는 완화하지 않았다. 원본미션은 변경하지 않았다. 날씨 동일통제는 미입증이다.

## 4. 원인 분석

확인: 현행5파트 baseline의 이 평지조건에서 실제 ETW 수집이3회 완료됐고 현재수집기의 종료코드누락은 재현되지 않았다. 값의 실행간 변동이 있으므로 단일유리값을 기준으로 후보이득을 판정하면 안 된다. 기존수동64의27.66ms는 자유플레이·접촉/높이변화 조건이며 이번고정평지와 동일작업량이 아니다. 과거오프라인65~70ms와도 직접속도비를 계산하지 않는다.

추정: 상태·접촉 분포,동일PC서버부하,표시모드·배경작업 등이 변동에 기여할 수 있다. 어느항목의순수CPU기여인지 분리측정하지 않았다. 새 게임코드변경이 없으므로 이번수치를새최적화효과로보고하지 않는다. 실제프레임별포즈부드러움은 Present/CPU Busy로판정할수없다.

## 8. 잔여 문제

현재평지baseline을보존하고다음최적화비교의기준으로사용한다. 다만사용자가관찰한밀집시버벅임은이평지반복만으로해결되지않았다. 다음단일산출물은기존자유플레이64의접촉밀집구간과이번평지의접촉solve/변위/계획률대조표이며,기존로그만사용해다음후보가실제고비용구간을겨냥하는지확인한다. 이미기각된Drive/Displace단순병합·rank·hit0Bounds를다시구현하지않는다. 새물리정밀도완화는근거·위험·중단조건을먼저정한뒤국소비교한다. 원인없는새보간/업데이트방식추가나기능복구연쇄로전환하지않는다.
