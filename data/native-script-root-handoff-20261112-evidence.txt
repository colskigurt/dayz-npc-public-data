## 1. 작업 목표

## 4. 원인 분석
확인: 기존DGNativeCommand의unmanaged ApplyRootMotion분기가현재모델에서엔진으로root를넘기고실제이동으로이어진다. nativeMove를계속교체하지않고기존애니메이션명령을유지할별도후보의능력근거다. 현재전체NPC는GroundBody분기가먼저실행되어이플래그만켜도같은결과가나오지않는다.
확인: 명령재생성은script Age/Owner.NativeSeconds의기준을초기화한다. 기존Traversal.NativePhaseAt/Settle의차분소비와결합하려면갱신순서·연속성·유효재기준이필요하다. 실제LAND/SETTLE시험은하지않았으므로착지가실패했다고보고하지않는다.
추정: 동일DG명령을유지하고지상root처리를엔진에넘기는방식은Move↔Script반복교체보다시간·수명위험을줄일수있다. 그러나기존transform Commit/논리readback/압력/Contacts·lift소유권과native충돌·지지의안전성은여전히해결되지않았다. 단순if한줄최적화나동등한물리교체로취급하지않는다.
미확인: 실제월드벽/발판가장자리/개체간접촉에서이경로의물리판정,피격·사망·수신체·낙하/재등반보존,전체CPU절감과64비용. rootAPI사용이nativequery를줄였거나더싼controller라는뜻은아니다.

# Native ground / scripted traversal — ownership contract review

Status: source-confirmed constraints; production handoff NOT implemented.

1. One transform authority. The current mission Commit writes render transforms every frame using delayed Presentation.Sample; native ground movement cannot run concurrently with those writes. Damage receiver synchronization must follow the selected authority. Native mode must not silently freeze its receiver or inventory.
2. Coordinate mapping. RenderOrigin = Agent.Position + Rotate(IdleOffset, heading) + Y*Lift; render yaw = heading+180. Native GetPosition is the actual rendered origin, not automatically the logical ground anchor. A handoff must preserve this mapping and accepted contact history, not force zero lift/idle or teleport to a delayed position.
3. Native-to-script entry. Snapshot position/orientation, previous accepted Contacts and lift, request/release/landing flags, recovery generation, pending combat, route, pressure state and graph instance. Validate the current pose before assigning a script-owned trajectory. Keep legitimate support loss/fall; do not force supported=true.
4. Script-to-native entry. Requires ground FOLLOW with no active traversal/fall/landing/combat/death lock, supported current pose and unambiguous commit ownership. A native result must be read back before perception/crowd/path progress consumes it. Failure preserves the old owner; no partial native activation with stale Agent.Position.
5. Command lifetime. Native StartCommand_* owns replacement/destruction. Never delete a live command manually. Existing HandleNativeCommand would recreate DGNativeCommand unless the isolated policy handles native ground explicitly.
6. Time. DGNativeCommand owns Age starting at zero and writes Owner.NativeSeconds; Traversal.SetPhase snapshots NativePhaseAt and Settle subtracts it. Recreating the command can reset the diagnostic/gameplay time base. This is not proof that the native graph clock resets. A future adapter needs monotonic phase timing or explicit valid rebasing without changing graph playback speed.
7. Contact semantics. DriveGround commits Contacts/Lift before Displace. Failed pressure preserves successful locomotion. Native equivalent support/contact and external lateral pressure APIs remain unverified. Do not collapse two accepted segments to one endpoint simply because native Move ran on flat ground.
8. Alternative to repeated command switching. Existing DGNativeCommand with no GroundBody and ApplyRootMotion=true uses PrePhys_SetTranslation(delta), then the engine applies physics. It could offer a stable command lifetime, but physics/support equivalence and full-NPC integration are unknown. Prior follower-root branch tests did not demonstrate unmanaged movement: their ApplyRootMotion=true actor also had GroundBody, selecting the zero-translation managed branch.

Next bounded capability experiment: one existing current-model actor, native idle/walk → unmanaged script walk with ApplyRootMotion → native walk/run → unmanaged script run → native idle. Same-request transitions are separated from clip changes. Record actual world motion, script/native command presence, callback counts, script Age diagnostic and graph UUID. Thirty game seconds, no CPU benchmark, no 8/64 expansion. Abort unexpected actor loss or >1m below terrain. This does not validate crowd pressure, support, climb or combat and cannot be adopted as a whole-NPC optimization.
