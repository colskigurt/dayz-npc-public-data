정상 표시8→64 및 실제 전체 복구 검사 수동 질의

작성: 2026-10-28T06:47:21.121008+09:00

1. 작업 목표

정상 표시 상태의 8→64명 회귀를 재실행하고, 정적 몸통 통과 가능성이 원래 animated joint/world/CoreClear 검사에서도 유효한지 질의한다. 현재 게임 동작은 보존하고 수동 질의 결과로 이동 명령을 만들지 않는다.

2. 실제 수행

- 매 실행에서 로딩 중 Sky activate_window를 사용하고 이후 실제 컨테이너/군집 장면을 확인했다. 관찰 시각은 profile의 window-visible-observation.json에 저장했다. 새 영상은 없으며 화면 관찰로 부드러움을 수용하지 않는다.
- 기존 B8FB PBO와 동일 그래픽을 유지한 phase 수동 미션으로8명/180초와64명/300초를 정상 종료했다. phase 조건은 FALL/LAND가2초 이상이고 현재 착지/본 접촉 이유가 막힌 경우다. 최대12개체, 초당1묶음, 기존8방향+접촉 접선2개+목표 각도5개를 비교했다.
- phase64 표본에는 기존 방향도 통과해, 두 번째 미션은 EscapeNoExitAt 2초 이상·PressureEscapeValid=false·최근 실패 계획(허용 창 max100ms/미션dt1.5배)으로 조건을 좁혔다. 표준 질의dt50ms/첫 걸음3cm를 기존·추가 방향 모두에 사용했다. 새 조건64명/300초도 별도 기록한다.
- 수집 조건 확장의 첫 컴파일은 Enforce 뺄셈 표기 오류로 실패했다. 실패 미션/compile 로그를 보존하고 공백을 명확히 한 별도 보관·재생성본에서 컴파일을 통과했다. 기본 미션/원시 로그는 덮어쓰지 않았다.
- 실제 질의가 쓰는 진단 필드19개를 복원하고 위치·heading·phase·기존 escape 목표/valid·NextRequest를 전후 비교했다. native AnimUpdates 변화가 있는 표본은 추가 방향의 독립 기회 집계에서 제외한다. managed peer 접촉 정책은 원래 그대로며 별도 crowd 상호작용을 실행한 것은 아니다.

4. 원인 분석

확인: 이전 저주기 환경과 달리 정상 창의8명은 최종8/8·고지대 누락0,20/33/35ms로 돌아왔다. 새 수동 질의가0회인8명에서 이를 이유로 NPC 이동 개선이나 질의 안전성을 주장하지 않는다.

확인: phase64에서 원래 전체 검사를 실제 현재 포즈로 질의할 수 있었고, 선택된 필드/불변식을 원상 복원한 기록을 얻었다. 그러나 최초 조건은 착지 공간이 아직 막혔어도 옆으로 복구 중인 낙하를 포함해, 기존 방향 고갈을 직접 나타내지 않았다. 따라서 조건을 원래 계획의 no-exit 시간으로 좁혔다.

5. 검증 수준

- 정상 표시8명: 해당 단회 최종·고지대 기준 통과, 질의는 미발동.
- 실제 전체 첫 걸음 질의: 진단 성공. selected-state 원상 복원과 native 갱신 카운터 안정 여부를 각 표본에 기록했다. 프로세스 전체 메모리 동등성 증명은 아니다.
- 64명 종료 계약: 두 실행64/64 관측. 정상 낙하와 복귀는 허용하며 중간 고지대 누락을 자동으로 terminal 실패로 바꾸지 않는다. 전체 기능 수용은 별도이고, 동일 조건 반복 회귀 수용도 아니다.
- 이동 후보 구현/실제 개선·시각 부드러움·20ms 성능 수용: 미실행/미수용. 현재 골은 미완료다.

6. 변경 사항

게임 PBO B8FBAB746F50CB7C8BDBB23E059C308298CEA5F57B4AC6BD0F2DDEBC55B8C185와 원래 미션은 보존했다. PBO 새 빌드/서명은 없고 기존3개 서명 검증 성공. 정상 낙하·복구·벽/발판 gate를 완화하지 않았다. 운영 서버 변경 없음.

별도 source7EA3030F…phase 미션과1BC6DADE…stalled 미션, 그 staged/engine 결과를 보존했다. launcher는 기본 OFF EscapeShadow 옵션에 phase/stalled 선택을 추가했고 새 실행부터 launcher-source.ps1/해시를 profile에 보관한다. actual executed init.c는 모든 profile에 보존한다. analyze_horde_missed_surface.py는 발동하지 않아 없는 egress 후보 저널을 선택 증거 부재로 명시하고, 중간 도달 집계는 원래 ground/player 기록으로 유지하도록 수정했다.

8. 잔여 문제

1. 정체 표본에 추가 방향만 통과하는 경우가 있으면 원래 sweep/peer/지원 검사를 유지한 소수 후보를 설계하고 opt-in8→64 실제 실행으로 검증한다. 표본 부족/불통과이면 포즈·initial contact·EGRESS 진단을 더 좁히고 임의 방향을 추가하지 않는다.
2. 혼잡/착지 차단/재등반·고지대 미도달을 최종 도착으로 덮지 않는다. 단회 차이를 인과나 최적화로 해석하지 않고 조건/순서 교차 반복을 유지한다.
3. 애니메이션은 CPU 포즈/실제 표시 시간과 buffer 연속성에 집중하고 새 보간을 추측 적용하지 않는다. 64명 비용은 별도4조건/반복 실험에서 귀속하며 native 그래프/GPU/할당·GC 미확보 범위를 명시한다.
4. 이번 묶음은 추가만 통과하는 근거를 확보하지 못했으므로 방향 추가를 채택하지 않는다. 원래 계획이 첫 걸음은 허용한 뒤 진행 중 막히는 EGRESS 전이는 기록으로 분리해 유지한다. 다음 실험 우선순위는 기존1개체 CPU/표시 연결의 pose buffer 교체 연속성이다.
